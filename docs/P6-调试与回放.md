# P6 调试与回放（view-only）

## Context

多 Agent 系统的核心维护痛点：**一旦输出不对，无法回溯**。当前 chahua envelope 流虽然
含了多数信号（`turn_start.scores` 已带 raw、`tool_start/complete` 已 emit），但全部是
**ephemeral WebSocket**，关掉前端窗口就没了；prompt（scoring + speak）连 envelope 都不进，
只活在内存。

对齐 AutoGen Studio 的核心能力——**每一轮可展开看**：
谁被候选 / 各自分数 / 为什么被选 / prompt 内容 / 用了哪些工具 / 哪些 MCP / 产物在哪。

本节只做 **取证视图（view-only）**：把现有 in-memory 与 envelope 数据落盘 +
新增右侧抽屉式 UI 展开看。**不实现** prompt 重跑 / 工具回放（与 agentao 侧
deterministic seed / tool 拦截耦合太深，留 P+1）。

---

## 阶段划分（评审后切分）

**P6.1：后端落盘**。`debug_recorder.py` + `[debug]` config + orchestrator/guest/transport
hooks。完成后 `rooms/<id>/debug/turns.jsonl` 与 `prompts/<turn_id>/*.txt` 齐全。
**前端零改动**，开发者直接读盘排查。

**P6.2：前端实时调试抽屉**。`debug_panel.js` 消费**实时 envelope 流**
（`TURN_START` / `MESSAGE_START` / `TOOL_START` / `TOOL_COMPLETE` / `MESSAGE_END`），
不读历史。抽屉与 task_panel **互斥**占用右侧 `<aside>` 槽。打开调试时关任务面板，反之亦然。

**P6.3（不在本次范围）**：历史 `turns_index` 进 `room_history` + `FETCH_TURN_DETAIL`
inbound + `TURN_DETAIL` envelope。等 P6.2 用起来确认有价值后再上。

本文档下面 §1-§7 是 P6.1，§8-§10 是 P6.2。

### 实施顺序（评审收尾建议）

落地建议按这条递增链路走，每一步可单独提 PR 并跑测：

## 决策

| | 决定 | |
|---|---|---|
| 回放语义 | **只看** | 不重跑 |
| 捕获默认 | **默认开** | `room.toml [debug] enabled = false` 可关 |
| Prompt 捕获默认 | **默认开** | `capture_prompts = false` 可单独关 |
| 存储位置 | **房间级** `rooms/<id>/debug/` | 与 transcript/summary 同级，跨 task |
| UI 槽位 | **与 task_panel 互斥** | 同一右侧 `<aside>`，不堆叠 |

**`capture_prompts` 默认开的理由**：与全局 `enabled` 同口径——bug 发生前没人会去开，
默认 off 等于"等 bug 复现后再开"，但 bug 已经过去。

**隐私警告**（写进文档）：prompt 中含 `USER.md`（用户偏好可能含隐私段）、任务 goal、
工具参数（可能含文件片段）。**`rooms/<id>/debug/` 应进 `.gitignore`**（与 `.env` 同口径），
不要 commit 到代码仓 / 不要随 export 分享。后续若有"export 房间"功能默认排除 `debug/`。

## 数据模型

### 文件布局

```
rooms/<id>/debug/
├── turns.jsonl                       # 每个 pick 周期一行（一条 turn 摘要）
└── prompts/<turn_id>/                # capture_prompts=false 时本目录不创建
    ├── scoring_<guest>.txt           # 每位被打分茶客一份完整 prompt
    └── speak_<message_id>.txt        # 每位发言茶客一份完整 context_message
```

**为什么 prompt 走旁路文件**：单条 scoring prompt ~2-4KB，speak prompt ~5-20KB；
塞进 jsonl 会让"快速扫 turns.jsonl 做分析"变慢且不便 grep。

### `turns.jsonl` 行 schema

```json
{
  "schema_version": 1,
  "turn_id": "turn_<hex>",
  "ts_ms": 1731912345678,
  "task_id": "task_<hex>",
  "trigger": {
    "kind": "user_msg" | "ai_chain",
    "ref_seq": 42
  },
  "scoring": {
    "threshold": 0.65,
    "scorables": ["Alice", "Bob"],
    "cooled": ["Charlie"],
    "results": [
      { "guest": "Alice", "score": 0.72, "kind": "scored",
        "raw": "{\"score\":0.72,\"reason\":\"...\"}",
        "prompt_file": "prompts/turn_xxx/scoring_Alice.txt" },
      { "guest": "Bob", "score": 0.30, "kind": "scored", "raw": "...",
        "prompt_file": "prompts/turn_xxx/scoring_Bob.txt" },
      { "guest": "Charlie", "score": 0.0, "kind": "cooldown", "raw": "" }
    ],
    "winners": ["Alice"]
  },
  "scoring_path": "scoring",
  "messages": [
    {
      "message_id": "msg_<hex>",
      "guest": "Alice",
      "speak_prompt_file": "prompts/turn_xxx/speak_msg_xxx.txt",
      "status": "ok",
      "seq": 43,
      "tool_calls": [
        { "call_id": "...",
          "tool": "task_write_artifact",
          "args": {"name": "draft.md", "content": "..."},
          "source": "builtin",
          "mcp_server": null,
          "status": "ok", "duration_ms": 123, "error": null }
      ],
      "artifact_paths": ["tasks/task_xxx/artifacts/draft.md"]
    }
  ]
}
```

**字段口径**：
- `prompt_file` / `speak_prompt_file` 在 `capture_prompts=false` 时整字段缺省（不空串）。
- 没有 `thinking_chunks` / `delta_chars` —— 要 stats 后续补 hook。
- `trigger.kind ∈ {"user_msg", "ai_chain"}`。**P6.1 不区分合成用户消息**（P5.5 的
  `_kick_synthesized_user_message` 也归 `user_msg`，理由见 §「不在范围」）。
- `winners` 可为 `[]`（"无人接话"也记一行 —— 见下面规则）；`messages` 在 `winners=[]`
  时为空数组。
- `scoring.threshold` 在 mention / broadcast / 全员冷却路径上为 `null`（这些路径不走打分）。
- `scoring.results[].kind ∈ {"scored", "mention", "cooldown", "error"}`（**评审第 4 条**：
  对齐 `ScoreKind` 实际值，删 `"broadcast"`，不引入新 `ScoreKind.BROADCAST`）。
- **`scoring_path`**：turn 级字段 `∈ {"scoring", "mention", "broadcast"}`，区分本周期走
  的是哪条路径。这是 mention 与 broadcast 唯一可观察的差异 ——
  - `"scoring"`：常规 LLM 打分（`threshold ≠ null`）。
  - `"mention"`：单 @ 路由（results 中仅命中那位 `kind="mention"`）。
  - `"broadcast"`：@all / @所有人（results 中所有 guest 都是 `kind="mention"`）。
- **`tool_calls[].source`**（评审第 3 条）：`∈ {"builtin", "mcp", "unknown"}`。
  从 tool name 启发式判别：以 `mcp__` 前缀（agentao MCP 工具命名约定）→ `"mcp"`，
  从 `mcp__<server>__<tool>` 拆出 `mcp_server`；否则 `"builtin"`，`mcp_server=null`；
  无法识别时 `"unknown"`。**不依赖 agentao 显式 event 字段** —— 命名启发式即够回答
  "哪些 MCP 被调用"，命名约定一旦变只动一处。
- **`messages[].artifact_paths`**（评审第 2 条）：本条消息内**派生**的产物绝对路径
  （`tasks/<task_id>/artifacts/<name>` 格式）。**仅从特定写盘工具派生**：
  - `task_write_artifact(name, content)` → `tasks/<task_id>/artifacts/<name>`。
  - 后续若加更多明确写文件工具，按工具名扩派生映射，**不挂 `ArtifactDetector`**。
  - 派生时 `task_id` 取该消息所属 turn 的 `task_id`；`task_id=null` 时跳过（不入 task）。
  - `tool_calls.args` 不变（保留工具原始 args），`artifact_paths` 是单独的派生字段。
  - 字段为 `[]` 表示本条消息无产物（不缺省，方便扫描）。

**"每个 pick 周期一行"规则**（评审强调）：
最需要调试的就是"**为什么没人说话**"。所以即便 `winners=[]`（全员低分），
**仍写一行 `turns.jsonl`**，让 `scoring.results` 完整保留所有候选与各自分数 / 原因。
**`scorables=[]` 且无 @mention 的纯冷却空转也必须记一行**：
`threshold=null`、`scorables=[]`、`cooled=all_guests`、`results=` 每位 guest 一条
`kind="cooldown"` 0 分占位。**无可选分支** —— "为什么这个 pick 周期没人说话"必须可追溯。

**`turn_start` envelope 不为 `winners=[]` 而 emit**（与现状一致，避免前端协议变化）。
P6.2 实时面板：`winners=[]` 的 pick 周期在前端不可见；开发者从盘上 `turns.jsonl` 看。

**落盘宽容**：用 `read_jsonl_skip_bad`（同 `transcript.jsonl` 口径）。未知字段 warn 忽略，
必需字段缺才跳条。`schema_version` 字段为未来扩展留余地。

## P6.1：后端落盘

### 1. `chahua/debug_recorder.py`（新文件）

```python
class TurnRecorder:
    """房间级 debug 落盘 facade。Orchestrator/Guest/Transport 在 splice 点调本对象。

    无内部并发态——同一 room 的 pick 周期是串行的（Orchestrator while 循环），所以一份
    in-flight 数据 `self._current: dict | None` 够用。多房间各自一个 recorder 实例。
    """
    def __init__(self, room_dir: Path, *, enabled: bool, capture_prompts: bool): ...
    def start_turn(self, *, turn_id: str, task_id: str|None, trigger: dict) -> None: ...
    def record_scoring(self, *, threshold, scorables, cooled,
                       results: list[tuple[ScoreResult, str|None]],  # (result, prompt)
                       winners) -> None: ...
    def record_message_start(self, *, message_id, guest, speak_prompt: str) -> None: ...
    def record_tool(self, *, message_id, call_id, tool, args,
                    source, mcp_server,                  # 新：MCP 启发式判别
                    status, duration_ms, error) -> None: ...
    def record_artifact_path(self, *, message_id, path: str) -> None: ...  # 派生产物路径
    def record_message_end(self, *, message_id, status, seq) -> None: ...
    def flush_turn(self) -> None: ...      # 写一行 turns.jsonl（cancel / error 也走这里）
    def discard_turn(self) -> None: ...    # 仅供 recorder 内部状态损坏时丢 in-flight

NOOP_RECORDER  # enabled=False 时所有方法 no-op；同 NOOP_SINK 风格
```

复用 `chahua/_persist.py::append_jsonl` 与 `write_text_atomic`，与 transcript / room.toml
共用同一组持久化原语。

**注入点**：`chahua/session.py::build_room_session` 内拿 `room_config.room_dir` 构造
recorder，再注入 orchestrator 与每位 guest。**`Room` 对象本身不持 recorder**——
debug 是侧路能力，Room 不感知。

### 2. `chahua/config.py`：新增 `[debug]` section

字段白名单（严格，未知字段 → `RoomConfigError`，同 `[room.llm]` 口径）：
- `enabled: bool = True`
- `capture_prompts: bool = True`

不做大小 cap（MVP 简单优先，超大房间用户自行删 `debug/` 目录；rotation 留 P+1）。

### 3. `chahua/scoring.py`：内部 `score_with_prompt`

**不改** `IntentScorer.score` 公契约 —— 它仍走 envelope 给前端，不污染 `ScoreResult` dataclass。

**新增** `IntentScorer.score_with_prompt(...) -> tuple[ScoreResult, str]`：内部多返回
一份 prompt 字符串。`score()` 内部改成 `result, _ = await self.score_with_prompt(...)`，
对老调用方零影响。

orchestrator 走 `score_with_prompt` 路径**仅在 `recorder.capture_prompts=True` 时**——
评审第 3 条：既然 `capture_prompts=false` 显式关了 prompt 捕获，prompt 字符串就**不该
扩散到 orchestrator 层**（避免内存中存在但不落盘的"半捕获"状态）。判断在
`_score_one` 入口：

```python
async def _score_one(name, ...):
    if self._recorder.capture_prompts:
        result, prompt = await self._scorer.score_with_prompt(...)
        return result, prompt
    return await self._scorer.score(...), None
```

`recorder.enabled=False` 时 `capture_prompts` 必为 False（NOOP 实例直接两个 attr 都是
False），所以这条单一条件就够覆盖"完全关 debug"与"开 debug 但不存 prompt"两个口径。

这样 scoring 的 prompt 拼装**单点在 `scoring.py` 内**，不泄到 orchestrator。

### 4. `chahua/orchestrator.py`：splice 点

- `__init__`：接受外部传入的 `recorder` 引用（不在 orchestrator 内部 new，让 session 装配
  统一管理）。

- **`_pick_next_speaker` 改签名**：始终返回 `(winners, scores, prompts_by_guest, debug_meta)`
  非 `None`（评审第 1+2 条）。
  - `winners`：list[str]，可为 `[]`（全员低分 / 全员冷却）。
  - `scores`：list[ScoreResult]，含所有候选（含 cooldown 那批 0 分占位）。
  - `prompts_by_guest`：dict[str, str|None]，`capture_prompts=False` 时为空 dict。
  - `debug_meta`：dict 仅供 recorder 用，含 `_pick_next_speaker` 内部已算出的字段，
    避免 `_run_ai_chain` 重算（评审第 2 条）：
    ```python
    {
      "threshold": float | None,    # mention / broadcast / 全员冷却路径为 None
      "scorables": list[str],        # 走 LLM 打分的候选；mention/broadcast/全员冷却 = []
      "cooled":    list[str],        # 进入 pick 时冷却中的茶客
    }
    ```
    不引入 dataclass —— dict 够用、字段少且只在 record_scoring 入口拆包。
  - 取消既有的 "return None" 路径 —— `_run_ai_chain` 不再用 `pick is None` 做控制流，
    改用 `if not winners` 判定"无人接话"。

- **`_run_ai_chain:275` 先 mint turn_id，无论 winners 是否为空都开一帧 turn record**：
  ```python
  winners, scores, prompts_by_guest, debug_meta = await self._pick_next_speaker(...)
  turn_id = new_turn_id()
  self._recorder.start_turn(
      turn_id=turn_id, task_id=active_task_id, trigger={"kind": ..., "ref_seq": ...},
  )
  self._recorder.record_scoring(
      threshold=debug_meta["threshold"],
      scorables=debug_meta["scorables"],
      cooled=debug_meta["cooled"],
      results=[(r, prompts_by_guest.get(r.guest_name)) for r in scores],
      winners=winners,
  )
  if not winners:
      self._recorder.flush_turn()     # 写一行后直接收手；不 emit turn_start envelope
      # 老 "pick is None" 路径上的 last_open_turn_id fixup 逻辑保留
      ...
      return
  # 正常发言路径：emit turn_start → speak → turn_end → flush_turn
  ```

  **trigger 来源**：`_consecutive_ai_turns == 0` → `user_msg`（取 transcript 最后一条
  `speaker_id="user"` 的 seq 作 ref_seq）；否则 `ai_chain`（ref_seq 取上一条 transcript
  seq）。**P6.1 不区分 `synthesized`** —— `_kick_synthesized_user_message` 最终也走
  `submit_user_message`，orchestrator 无从分辨，要分辨需新增 `submit_user_message(..., trigger_kind=...)`
  形参一路透传，本期不做（评审第 2 条）。

- `_run_ai_chain` 整轮结束（line ~325，`_kick_summarize` 之前）：
  ```python
  self._recorder.flush_turn()
  ```

- **cancel / 异常路径也 flush，不 discard**（评审第 5 条 —— 反转此前的 rollback 政策）：
  ```python
  except asyncio.CancelledError:
      self._emit_cancel_fixup(sink, turn_id=...)
      self._recorder.flush_turn()       # 保半截 prompt / 工具调用 / partial message
      raise
  ```
  逻辑：最需要排查的就是"取消时跑到哪一步"和"出错时 LLM 输出了什么"，把半截 turn 丢
  掉等于反向断了取证路径。各 message 的 `status` 字段已经能在行内区分 `ok` /
  `cancelled` / `error`，turn 行整体是否完整由 `messages[].status` 推断。

- `discard_turn()` 仅在 recorder 自身状态判定损坏时调（比如 in-flight `_current` 字段
  缺关键字段、序列化失败等），**正常 cancel / error 不调**。

- **不动 `_kick_detect_new_artifacts`**（artifacts 已在 `messages[].artifact_paths`
  通过工具名派生体现）。

### 5. `chahua/guest.py::TeaGuest.speak`

`TeaGuest.__init__` 多接一个 `recorder` 引用（与 `room` / `transport` 同款依赖，**ctor 注入**，
不设 setter）。

**对齐既有 `speak()` 结构**（评审第 4+5 条）—— context_message 由 orchestrator 在
`_let_speak()` 构造后**当形参传入**；`text` 取 `agent.arun` 的**返回值**；失败路径
读 `transport.partial_text`。recorder 调用以最小破坏面加进去（status / seq 用 finally 兜底）：

```python
async def speak(
    self,
    context_message: str,        # 既有签名不动；orchestrator 传入
    *,
    turn_id: str,
    sink: EnvelopeSink,
    cancellation_token: Optional[CancellationToken] = None,
    task_id: Optional[str] = None,
) -> Optional[Message]:
    message_id = new_message_id()
    status: str = STATUS_ERROR    # 悲观初始化
    msg: Optional[Message] = None
    try:
        with self._transport.bind(
            sink=sink, turn_id=turn_id, message_id=message_id, task_id=task_id,
            recorder=self._recorder,    # 新增：transport 在 _handle 里走 record_tool
        ):
            self._transport.emit_chahua(ChahuaEventType.MESSAGE_START, {})
            # context_message 已由 orchestrator 拼好，传入即记录；
            # capture_prompts=False 时 record_message_start 内部 no-op，不持有字符串引用。
            self._recorder.record_message_start(
                message_id=message_id, guest=self.name, speak_prompt=context_message,
            )
            try:
                text = await self.agent.arun(
                    context_message, cancellation_token=cancellation_token,
                )
            except (asyncio.CancelledError, KeyboardInterrupt):
                status = STATUS_CANCELLED
                self._emit_failure(STATUS_CANCELLED, "cancelled")
                raise
            except Exception as e:
                _log.exception("%s.speak() failed", self.name)
                # status 保持 STATUS_ERROR
                self._emit_failure(STATUS_ERROR, str(e))
                return None
            msg = self.room.append(
                self.name, text, message_id=message_id, task_id=task_id,
            )
            self._transport.emit_chahua(
                ChahuaEventType.MESSAGE_END,
                {"text": text}, status=STATUS_OK, seq=msg.seq,
            )
            status = STATUS_OK
            return msg
    finally:
        self._recorder.record_message_end(
            message_id=message_id,
            status=status,
            seq=msg.seq if msg is not None else None,
        )
```

要点：
- **`context_message` 是入参**，不在 `TeaGuest` 内部构造（无 `_build_context_for`）。
- **`text` 来自 `agent.arun` 的返回值**，不读 `self._partial`（失败路径才走
  `self._transport.partial_text`，由现有 `_emit_failure` helper 处理）。
- `status` 悲观初始化为 `STATUS_ERROR` —— 三条路径下 finally 永远拿到合法值。
- `msg` 仅 `STATUS_OK` 路径上被赋值；`finally` 用 `if msg is not None` 兜底取 seq。
- `record_message_end` 单点在 `finally`，三条出口路径（return msg / raise / return None）
  共用一行；`record_message_end` 自身 try/except 包到底（"recorder 失败不阻断房间运行"
  不变量）。
- `finally` 放在 `with bind(...)` **外面** —— recorder 不依赖 transport 绑定状态，
  且 bind 退出后调用更显安全。
- 现有 `message_end` envelope emit（三条路径，含 `_emit_failure` helper）**不动** ——
  本期只加 recorder 调用，不重构 envelope 路径。

### 6. `chahua/transport_bridge.py::ChahuaTransport._handle`

`TOOL_START` / `TOOL_COMPLETE` 分支内 `emit_chahua` 之后，**同步** call recorder：
```python
# TOOL_START
tool_name = data.get("tool") or ""
source, mcp_server = _classify_tool_source(tool_name)  # 见下面 helper
self._recorder.record_tool(
    message_id=self._message_id, call_id=data.get("call_id"),
    tool=tool_name, args=data.get("args"),
    source=source, mcp_server=mcp_server,
    status="started", duration_ms=None, error=None,
)
# 同分支顺手做 artifact 派生（仅 task_write_artifact）
if tool_name == "task_write_artifact" and self._task_id is not None:
    name = (data.get("args") or {}).get("name")
    if name:
        self._recorder.record_artifact_path(
            message_id=self._message_id,
            path=f"tasks/{self._task_id}/artifacts/{name}",
        )

# TOOL_COMPLETE
self._recorder.record_tool(
    message_id=self._message_id, call_id=data.get("call_id"),
    tool=data.get("tool"), args=None,        # complete 帧 args 不重复
    source=None, mcp_server=None,            # complete 帧不再判别（按 call_id 合并）
    status=data.get("status"), duration_ms=data.get("duration_ms"),
    error=data.get("error"),
)
```

`record_tool` 内部按 `call_id` 在 `messages[].tool_calls` 里合并同一调用的 start / complete
两半（source / mcp_server / args 取 start 帧，status / duration / error 取 complete 帧）。

**MCP 来源启发式** `_classify_tool_source(tool_name)`（module-level helper，单点）：
```python
def _classify_tool_source(tool: str) -> tuple[str, str | None]:
    # agentao MCP 工具命名：mcp__<server>__<tool_name>
    if tool.startswith("mcp__"):
        rest = tool[len("mcp__"):]
        server, _, _ = rest.partition("__")
        return ("mcp", server or None)
    if tool:
        return ("builtin", None)
    return ("unknown", None)
```

recorder 在 `bind()` 时由 caller 注入到 transport（同 sink 一起）。

## P6.2：前端实时调试抽屉

**评审第 1 条调整**：核心目标里"prompt 喂了哪些 transcript/summary"必须在 P6.2 看得到，
否则 P6.2 落地后用户回头还是要打开文件资源管理器。所以 P6.2 **必须能展开 prompt**，但
为避免历史协议复杂度，**只看实时本会话**的 prompt（已在内存的 envelope 里），不做

### 7.5 envelope 携带 prompt（capture_prompts=True 时）

为了让前端不必新增 inbound 就能展示 prompt，**在既有 envelope 的 `data` 里搭车**：
- `TURN_START.data.scoring_prompts: {guest: text}` —— `capture_prompts=True` 时附；
  老前端忽略未知字段。
- `MESSAGE_START.data.speak_prompt: text` —— 同上口径。

`capture_prompts=False` 时两个字段都缺省。

**为什么 piggyback 不另开 envelope 类型**：
- 时序天然对齐：scoring_prompts 与 turn_start 同帧到达，无须前端做 join。
- 协议面零增加：不动 `ChahuaEventType` 枚举、不动 `handleEnvelope` switch 形态。
- 大小可控：单 scoring prompt ~2-4KB、单 turn ~20KB 上限（N=5 茶客），本地 WS 完全 OK。
- schema_version 不 bump（同 `task_id`、`room_history.turns_index` 等过往 piggyback 口径）。

orchestrator 与 TeaGuest 内 emit 时：
```python
# orchestrator._run_ai_chain，emit turn_start
data = {"scores": [_score_to_dict(s) for s in scores]}
if self._recorder.capture_prompts and prompts_by_guest:
    data["scoring_prompts"] = {g: p for g, p in prompts_by_guest.items() if p}
self._emit_turn(sink, turn_id=turn_id, type=TURN_START, data=data)

# TeaGuest.speak，emit message_start
data = {}
if self._recorder.capture_prompts:
    data["speak_prompt"] = context_message
self._transport.emit_chahua(MESSAGE_START, data)
```

## 不变量延伸

加进 CLAUDE.md「关键不变量」节，与现有 P5.x 不变量同口径：

- **`turns.jsonl` 加载跳坏行**（同 transcript.jsonl 口径）。
- **`[debug]` section all-or-nothing**：写就全字段写，未知字段 → `RoomConfigError`
  （同 `[room.llm]` 口径）。
- **recorder 失败不阻断房间运行**：所有 `record_*` 方法 try/except 包到底，日志 WARN，
  房间正常跑下去（debug 是辅助能力，绝不能让它把生产路径挂掉）。
- **cancel / 异常路径仍 flush 一行**（评审第 5 条修正）：取消 / 失败时**不丢半截 turn** ——
  最需要排查的就是"取消时跑到哪一步 / 出错时 LLM 输出到哪"，丢了反而无证可查。各
  `messages[].status ∈ {ok, cancelled, error}` 已可逐条区分；turn 行整体永远有效。
  `discard_turn()` 仅供 recorder 自身状态损坏时使用，**不挂到 cancel / exception 路径**。
- **`debug/` 含敏感内容**：USER.md / 工具参数 / 任务上下文都进 prompt 文件，
  `rooms/*/debug/` 必须进 `.gitignore`；export 房间默认排除。
- **`capture_prompts=false` 时不创建 `prompts/` 目录**：避免空目录污染（同
  `share/` 在没文件时不建的口径）。
- **scoring prompt 渲染单点在 `scoring.py`**：`IntentScorer.score_with_prompt` 是唯一
  暴露 prompt 字符串的入口；orchestrator 不重新调 `_render_prompt`，避免双渲染漂移。
- **debug panel 与 task_panel 互斥占槽**：右侧 `<aside>` 同一时刻只显示一个，
  不堆叠不浮层。
- **每个 pick 周期一行 `turns.jsonl`**：`winners=[]` 也写一行 —— "为什么没人说话"
  本身就是最重要的调试场景；`turn_start` envelope 在 `winners=[]` 时不 emit（前端协议
  不变），P6.2 实时面板不显示这种 turn，开发者从盘上看。
- **`recorder.enabled=False ⇒ capture_prompts=False`**：NOOP 实例两个 attr 都是
  False；orchestrator 只用 `capture_prompts` 单条件分支决定是否走 `score_with_prompt`，
  不引入双层布尔判断。
- **`record_*` 全部 ctor 注入，无 setter**：TeaGuest / Orchestrator 构造期必传
  recorder，测试夹具传 `NOOP_RECORDER`；实现期没有"何时 set"的犹豫窗口。
- **MCP 来源走 tool 名启发式**：`mcp__<server>__<tool>` 前缀 → `source="mcp"` + 拆出
  `mcp_server`；否则 `"builtin"`。**不**为 debug 改 agentao event 形态；命名约定一旦
  变只需更新本一处启发式。
- **artifact 派生表显式枚举**：`messages[].artifact_paths` 仅从特定工具名派生
  （MVP 仅 `task_write_artifact`）；要加新工具必须显式扩派生表，**不挂 `ArtifactDetector`
  事件**（debug 是侧路能力，与任务系统解耦）。
- **prompt 走 envelope piggyback 不另开类型**：`TURN_START.data.scoring_prompts` /
  `MESSAGE_START.data.speak_prompt` 在 `capture_prompts=True` 时附；老前端忽略未知
  字段；`schema_version` 不 bump（与 `task_id` piggyback 同口径）。
- **piggyback 字段严格 enabled && capture_prompts 双开才出现**（评审收尾第 1 条）：
  任一条件为假 → 整字段**缺省（不写 key）**，**不传空字符串**。前端依此区分"prompt 捕获关了"
  与"prompt 是空"两种语义。
- **prompt 在前端 `<details>` 默认折叠 + 隔离于聊天 DOM**（评审收尾第 2 条）：
  prompt 文本只渲染在 debug panel 内部的 `<details><pre>` 容器里，**不进入主聊天
  `<ul id="messages">` 的 message text 路径**，避免（a）巨型 prompt 卡 UI、（b）误显示为
  聊天内容。`<details>` 默认 `open=false`，用户点开才解码渲染。
- **`_classify_tool_source` 仅 best-effort**（评审收尾第 3 条）：只看 tool 名前缀，
  不匹配 `mcp__<server>__<tool>` → `"builtin"`；空 tool 名 → `"unknown"`。
  **不为识别 MCP 反查 agentao 内部结构 / 不开新 agentao event**。命名约定一旦变只
  改启发式这一处。
