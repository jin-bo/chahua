## 从群聊到协作工作台：茶话室的任务房间

茶话室最初的形态是一间多 Agent 群聊室——几位由 agentao 驱动的 AI 茶客和你坐在同一聊天框里，可以 @、可以互相接话，像微信群一样自然。但群聊只是入口。一旦你需要这群 AI 真的帮你**把一件事做完**，而不只是聊聊，群聊的语义就不够了：消息会向前滚动，重要决策会被刷掉，谁负责什么没有锚点，AI 写出来的代码 / 文档散落各处找不回。

**任务房间** 是这个跃迁。它的思想很简单：在群聊里"开一个文件夹"。每个任务有自己的 `目标 / 负责人 / 状态 / 决策 / 产物` 五件套，所有围绕它的对话、产出都自动锚在这个文件夹上。同一聊天室里可以并行开多个任务，随时切换 active，互不污染。

它真正特别的地方是**三条信息通道**同时打通：

**通道 1 —— Prompt 注入。** 每次茶客准备发言前，茶话室会把当前任务的标题、目标、近期决策、最近产物、近期进展自动拼到喂给 LLM 的上下文里。换句话说，AI 茶客不需要被反复"提醒"——任务视野是它每一句话的底色。

**通道 2 —— `./task/` 工作目录。** 每位茶客在自己的工作目录下都看到一个 `./task/` 软链，指向当前任务的产物目录。茶客把文件写到 `./task/<name>`，等同于把产物入到这个任务里——下一刻就出现在任务面板的"产物"清单，所有人都能看到。无需上传、无需归集、无需点"添加"按钮。

**通道 3 —— 任务工具。** 茶客可以直接查询任务产物清单、可以**提议**开新任务、可以**提议**记一条决策。注意是"提议"——写权限永远在用户手里：茶客发出的提议会以卡片形式出现在聊天流里，由你点"采纳"才进库。这条规矩是刻意的，它防止 AI 之间自我接龙生成 50 个空任务，让人类始终是协作的锚点。

这套结构在工程上有几条不变量在兜底，普通用户感受不到但很关键：任务文件的入站校验**严格**（前端写错字段直接拒），落盘加载**宽容**（坏行跳过不让一个错文件让整个房间起不来），任务级摘要按需后台增量产出，多任务切换前会自动取消 in-flight 的发言避免错挂。这些是企业级协作所必须的——单机闲聊容忍不了的丢数据 / 错归类 / 状态错乱，到了多人多任务并行就会立刻被放大成事故。

把这些拼起来看：

- 群聊层让多个专长不同的 AI 自然协作；
- 任务房间层给协作绑上目标、决策、产物三个锚；
- 写权限边界让人类始终拍板；
- 自动归集让 AI 产出**默认就**入到正确的地方，不需要事后整理。

这就是**企业级多智能体协同平台**的雏形——不是更花哨的群聊，而是把"一群 AI 一起把一件事做完"的全链路工程化。茶话室还在加速：通道 1 / 2 / 3 已经合龙，任务采纳闭环、自动归集、多任务并存都已上线；接下来会在跨房间引用、长周期任务归档、团队协作（多人接入同一房间）这些方向继续推进。目标始终一致：**让 AI 协作从"聊天"变成"交付"**。
