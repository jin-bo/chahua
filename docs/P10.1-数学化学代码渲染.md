- **安全配置硬编码**（决策P10.1-5，本相位实质）：KaTeX `trust:false`（默认即此，禁

- **不**走「marked 后在 DOM 上 KaTeX auto-render 文本节点走查」（观澜 P4.14 的路子）——
  茶话室 marked 的反斜杠转义会先吃掉 TeX 内部 `\,`/`\\`/`\{`/`\_`/`\%`/`\&` 与 `\(`/`\[` 分隔符
  本身（§1.2 实测）。必须用 marked 扩展在转义前封箱（决策P10.1-3）。
- **不**支持 `\(…\)` / `\[…\]` 分隔符（MVP）—— 它们会被 marked 转义降级为 `(…)` / `[…]`；扩展
  里抢在转义前匹配虽可行但与内置 escape tokenizer 抢位需谨慎，且 LLM 主流输出是 `$…$` /
  `$$…$$`。只认这两支，与观澜「优先无歧义分隔符」结论一致但收得更紧（决策P10.1-3）。
- **不**把 KaTeX 产物塞进 `renderMarkdown` 再过 DOMPurify —— DOMPurify(`USE_PROFILES.html`)
  会剥掉 KaTeX 的内联 `style` / MathML、破排版；且 parse-time 渲染会在每个流式 delta 上跑
  KaTeX（半截公式抛错 + 性能）。故 KaTeX 在 **DOMPurify 之后、live DOM** 上渲、只在 message_end
  调一次（决策P10.1-4，同 mermaid「不在流式 delta 期间渲」）。
- **不**渲裸 `\ce{}` / `\pu{}`（无分隔符）—— mhchem 是 math-mode 宏，须写在 `$…$` 内（决策P10.1-2）。
- **不**做服务端 / CLI / MCP 渲染（决策P10.1-9，同 P10）：文本通道，渲染是宿主呈现层职责。
  CLI REPL 回字面源码（honest）。
- **不**改 CSP（§4.5 论证现有 CSP 已覆盖三类新资源）、**不**改 transcript / envelope /
  `schema_version` / 任何后端模块（纯前端）。
- **不**预留深色 / 浅色切换接口（茶话室单档配色，避免过度设计，决策P10.1-6）。

## 1. 现状与本质差异

### 1.1 现状

茶客气泡的 markdown 经 `renderMarkdown(text)`（`chat_view.js:18`）走
`marked.parse → DOMPurify.sanitize` 落 `innerHTML`：

```text
$E = mc^2$               → 字面 "$E = mc^2$"（marked 不识 math 分隔符，原样穿过）
$$\nabla \cdot \vec E$$  → 字面（且内部 \, 这类反斜杠会被 marked 吃掉，见 §1.2）
$\ce{2H2 + O2 -> 2H2O}$  → 字面文本（化学 mhchem 须在分隔符内，决策P10.1-2）
```python\nfor x in xs: ...\n```  → <pre><code class="language-python">…</code></pre>（无高亮、暗底纯字）
```

LLM 茶客综合答案时常写公式表达定义 / 推导、写 `$\ce{}$` 表达反应式、贴代码片段佐证；用户也
会手写。P10.1 补这层「最后一公里」：**同一段 markdown 在气泡里成公式 / 成色，在 transcript /
CLI 纯文本回退里仍是 honest 源码**。

### 1.2 与观澜 P4.14 的本质差异（茶话室的核心难点）

| 维度 | 观澜（P4.14，FastAPI Web 宿主） | 茶话室（P10.1，Electron 渲染进程） |
|---|---|---|
| markdown 渲染处 | **服务端** python-markdown（`render.py`），转义姿态 `_EscapeHtmlExtension` | **客户端** `marked.parse → DOMPurify.sanitize`（`chat_view.js`） |
| 硬约束 | **服务端零改 / 字节稳定不破**（KaTeX auto-render 在 DOM 文本节点就地走查） | **marked 的 CommonMark 反斜杠转义会先吃掉 TeX**（须在转义前封箱） |
| 数学拾取 | `renderMathInElement(container)` 遍历文本节点按分隔符排版 | **marked 扩展** tokenizer 封箱 → carrier 节点 → KaTeX 逐节点 `render` |
| 运行时承载 | vendored UMD + 注入 `<script>` / `<link>`（非 npm、无 build） | npm 包 + 动态 `import()`（与 mermaid 同范式） |
| 代码高亮 | highlight.js（与 mermaid 同 `code.language-X` 载体，机械复刻） | 同左（marked 的 `fenced_code` 也 emit `code.language-X`） |

**核心难点实测**（`node` 跑 `marked@18.0.3`，`gfm:true, breaks:true`）：

```text
IN : "block $$\int_0^1 x\,dx$$ end"     OUT: "<p>block $$\int_0^1 x,dx$$ end</p>"   ← \, 被吃成 ,
IN : "paren \(a+b\) end"                OUT: "<p>paren (a+b) end</p>"               ← \( \) 被降级
IN : "bracket \[a+b\] end"              OUT: "<p>bracket [a+b] end</p>"             ← \[ \] 被降级
IN : "inline $E=mc^2$ done"             OUT: "<p>inline $E=mc^2$ done</p>"          ← 无内部反斜杠者幸存
```

CommonMark 规定反斜杠后接 ASCII 标点即转义剥除，故 `\,` `\\` `\{` `\}` `\_` `\%` `\&` `\$`
（TeX/mhchem 极常用）会在 KaTeX 看到之前被 marked 吃掉，`\(` `\[` 分隔符本身亦被降级。

> **这就是观澜 P4.14「marked 后在 DOM 上 auto-render」的路子在茶话室不成立的原因。** 茶话室
> 必须用 **marked 扩展**：tokenizer 命中即把整段 `$…$` / `$$…$$`（含内部所有反斜杠）作为单一
> token **原样收走**、marked 不再 re-lex 其内部 → TeX 字面零损耗到达 carrier 节点，KaTeX 延后
> 渲（决策P10.1-3）。这是本相位**唯一的新机制**，§3.1 详述。

落点（与 P10 mermaid 同骨架，三类增强**区域不相交**）：

| 内容类型 | renderMarkdown 后的 DOM 载体 | 拾取选择器 | 渲染器 |
|---|---|---|---|
| **代码高亮** | `<pre><code class="language-X">转义源</code></pre>`（marked `fenced_code`） | `pre>code[class*="language-"]`（跳 mermaid / `.hljs`） | **highlight.js** v11（`@highlightjs/cdn-assets` es bundle） |
| **数学 / 化学** | `<span class="math-tex math-inline\|math-display">转义 TeX</span>`（marked 扩展 carrier） | `span.math-tex:not(.math-done)` | **KaTeX + mhchem** 逐节点 render |
| **mermaid**（P10） | `<pre><code class="language-mermaid">` | `pre>code.language-mermaid` | mermaid（不动） |

## 3. 拾取与渲染（marked 扩展 + 三增强 + 一编排器）

### 3.1 marked 数学扩展（`chat_view.js`）—— 转义前封箱（茶话室核心）

把 `$…$` / `$$…$$` 在 CommonMark 反斜杠转义吃到 TeX 之前「封箱」成单一 token；renderer 产出
carrier 节点，**只携带原样 TeX 文本 + class**（最小集，DOMPurify `html` profile 天然放行
`span` + `class`，§4），不在此处调 KaTeX。

```js
// HTML escape：carrier 文本里的 < & " 等转义，防注入（DOMPurify 还会再守一道，§4）。
function escapeHtml(s) {
  return (s || "").replace(/[&<>"]/g, (c) =>
    ({ "&": "&amp;", "<": "&lt;", ">": "&gt;", '"': "&quot;" }[c]));
}

// marked 行内扩展：display（$$…$$）须先于 inline（$…$）注册（长匹配优先）。tokenizer 命中
// 即把整段（含分隔符内的 \, \\ \{ 等）作为单一 token 原样收走，marked 不再 re-lex 其内部 →
// TeX 字面零损耗到达 carrier。$ 货币歧义（"$5 … $10"）由 inline pandoc 风格正则收窄（开 $ 后不
// 接空白/数字、闭 $ 前不接空白、闭 $ 后不接数字）；代价是数字开头行内公式（"$2x$"）也被拒，
// honest 残留——写 "$$2x$$" 或以字母/命令开头规避，决策P10.1-3。
marked.use({
  extensions: [
    {
      name: "mathDisplay", level: "inline",
      start(src) { const i = src.indexOf("$$"); return i < 0 ? undefined : i; },
      tokenizer(src) {
        const m = /^\$\$([\s\S]+?)\$\$/.exec(src);
        if (!m) return;
        return { type: "mathDisplay", raw: m[0], text: m[1] };
      },
      renderer(t) { return `<span class="math-tex math-display">${escapeHtml(t.text)}</span>`; },
    },
    {
      name: "mathInline", level: "inline",
      start(src) { const i = src.indexOf("$"); return i < 0 ? undefined : i; },
      tokenizer(src) {
        // pandoc 风格收窄货币歧义（$$ 已被 mathDisplay 先吃，这里只认单 $）：
        //   开 $ 后不接 空白/数字（拒 "$5"、"$ x"）、闭 $ 前不接空白、闭 $ 后不接数字
        //   （拒 "$5 and $10"、"it costs $20"）；内部可含转义 \$。
        const m = /^\$(?![\s\d])((?:[^$\n]|\\\$)*?[^\s])\$(?!\d)/.exec(src);
        if (!m) return;
        return { type: "mathInline", raw: m[0], text: m[1] };
      },
      renderer(t) { return `<span class="math-tex math-inline">${escapeHtml(t.text)}</span>`; },
    },
  ],
});
```

- **为何 carrier 而非 parse-time 渲 KaTeX**（决策P10.1-4）：① DOMPurify 会剥 KaTeX 内联 style /
  MathML；② 流式每个 delta 都重渲 `innerHTML`（`chat_stream.js:206`），parse-time 渲会在半截
  公式上反复跑 KaTeX（抛错 + 性能）。carrier 把「源在 markdown 里」与「富渲延后」解耦，与
  mermaid 完全同构（mermaid 也是 `code.language-mermaid` carrier + `renderMermaidIn` 延后）。
- **流式期间 carrier 显示原样 TeX 文本**（honest，像 mermaid 源显示为代码），message_end 才经
  `enhanceContent → typesetMath` 渲成公式。半截 `$E=mc^` 无闭合 `$` → tokenizer 不命中、留字面，
  无闪烁（同 mermaid 不变量）。

### 3.2 数学 / 化学 typeset（`chat_view.js`）—— KaTeX live-DOM + `trust:false`

```js
const KATEX_OPTS = {                          // 硬编码、无放宽旋钮（决策P10.1-5）
  throwOnError: false,                        // 语法错 → 错误色源码、不抛（决策P10.1-7）
  trust: false,                               // 安全铰链（KaTeX 默认即此，显式写明）：
                                              //   禁 \href/\url/\includegraphics/\html*（§4）
  strict: "ignore",                           // 仅静默告警，非安全项
  // 不设 macros → 每次 katex.render 自带默认 macros:{}，**逐公式隔离**：连同气泡内都不跨公式
  // 泄漏 \gdef/\newcommand（比观澜 auto-render「每容器一份」隔离更强，§4-③）。
};

let katexPromise = null;
function loadKatex() {                         // 懒加载单例（同 loadMermaid 范式）
  if (katexPromise) return katexPromise;
  katexPromise = import("../node_modules/katex/dist/katex.mjs")
    .then((mod) => {
      const katex = mod.default || mod;
      // mhchem：副作用 import，载入后注册 \ce/\pu 进 katex（须在 katex 之后）。
      return import("../node_modules/katex/dist/contrib/mhchem.mjs").then(() => {
        // katex.min.css 必需（排版定位 + @font-face 字体同源懒拉）；懒注入 <link>，CSP 不改。
        if (!document.getElementById("katex-css")) {
          const l = document.createElement("link");
          l.id = "katex-css"; l.rel = "stylesheet";
          l.href = "../node_modules/katex/dist/katex.min.css";
          document.head.appendChild(l);
        }
        return katex;
      });
    })
    .catch((err) => { katexPromise = null; throw err; });   // 失败不缓存、可重试（同 mermaid）
  return katexPromise;
}

export function typesetMath(container) {
  if (!container) return;
  const nodes = container.querySelectorAll("span.math-tex:not(.math-done)");
  if (nodes.length === 0) return;              // 早退：无 carrier 零加载（懒，决策P10.1-1）
  loadKatex().then((katex) => {
    for (const el of nodes) {
      if (!el.isConnected || el.classList.contains("math-done")) continue;  // await 间被重绘
      const tex = el.textContent || "";
      const displayMode = el.classList.contains("math-display");
      el.classList.add("math-done");           // 幂等排重（重入同 container 不重渲）
      try { katex.render(tex, el, { ...KATEX_OPTS, displayMode }); }
      catch { /* throwOnError:false 已兜底；极端异常 → 保留原 TeX 文本（决策P10.1-7）*/ }
    }
  }).catch((err) => { console.warn("[chahua] KaTeX 加载失败：", err); });  // → carrier 留字面
}
```

- **KaTeX 在 DOMPurify 之后、live DOM 上渲**：`katex.render(tex, el, opts)` 把 `el` 内容替换为
  KaTeX 产物。该产物**不再经 DOMPurify**（已过那道），内联 style / MathML 因此存活；安全靠
  `trust:false` + 钉版 + CSP 自洽（§4-②）。carrier `textContent` = 原样 TeX（浏览器反转义），
  KaTeX 当 **TeX 解析、非 HTML**。
- **化学 = 数学同运行时**：`$\ce{2H2 + O2 -> 2H2O}$` 经 mhchem（载入注册进 KaTeX）排版；裸
  `\ce{}`（无 `$`）不被 marked 扩展封箱、按字面文本留存（决策P10.1-2）。

### 3.3 代码高亮（`chat_view.js`）—— 机械复刻 mermaid 载体

```js
export function highlightCode(container) {
  if (!container) return;
  const blocks = [...container.querySelectorAll('pre > code[class*="language-"]')].filter(
    (c) => !c.classList.contains("language-mermaid") && !c.classList.contains("hljs")  // 跳 mermaid / 已高亮
  );
  if (blocks.length === 0) return;             // 早退：无可高亮块零加载（懒，决策P10.1-1）
  loadHljs().then((hljs) => {
    for (const code of blocks) {
      if (!code.isConnected || code.classList.contains("hljs")) continue;
      const lang = (code.className.match(/language-([\w-]+)/) || [])[1];
      if (!lang || lang === "mermaid" || !hljs.getLanguage(lang)) continue;  // 未注册 → 纯文本（决策P10.1-7）
      try { hljs.highlightElement(code); } catch { /* 单块异常 → 保留纯文本 */ }
    }
  }).catch((err) => { console.warn("[chahua] highlight.js 加载失败：", err); });
}
```

- 载体 `pre>code.language-X` 与 mermaid **同一契约**（marked `fenced_code`），唯三差异：跳

  语言（保字面、不静默失败，决策P10.1-7）。
- highlight.js v11 `highlightElement` 读 `.textContent`（已转义源、反转义为代码文本）、产物**只**
  是 `<span class="hljs-*">转义文本</span>`，v11 移除 HTML 透传 → 输入不当 HTML（§4-①）。

> **highlight.js ESM 入口（承重坑，code-review 修正）**：**必须用 `@highlightjs/cdn-assets` 的
> `es/highlight.min.js`**（自包含浏览器 ESM、零相对 import / 零 CJS 标记，实测可在沙箱渲染进程
> dynamic import）。**`highlight.js` npm 包的 `es/common.js`/`es/core.js`/`es/index.js` 都是把 CJS

## 4. 安全分析（**本相位实质**）　**\[决策P10.1-5]**

茶话室渲染进程的 XSS 纵深防御靠 **`marked → DOMPurify` 客户端管线** + **Electron CSP**
（`script-src 'self'`、`style-src 'self' 'unsafe-inline'`、`default-src 'self'`、
`img-src 'self' data: blob:`，`index.html:10`）。P10 mermaid 首次让「内容→ `innerHTML` 注入」
（SVG，手工 sanitize 守）。P10.1 新增**两个**注入面（highlight 高亮 span、KaTeX 排版 DOM），
故安全分析仍是核心。

**威胁模型**：恶意茶客 / 用户写一段代码块或公式，企图让产物携带 `<script>` / 事件处理器 /
`javascript:` 链接，经渲染进程注入后以**同源**身份调本地 ws / 文件 API。

**逐渲染器论证「为何挡得住」：**

**① 代码高亮（highlight.js v11）：** 输入是 `code.textContent`（DOMPurify 已过、浏览器反转义为
字面字符），highlight.js 当**代码源 token 化**、从不当 HTML 解析；产物仅 `<span class="hljs-*">
转义文本</span>`（class 取自固定词表），v11 **移除 HTML 透传**（未转义 HTML 被剥除并 console
告警）。信任铰链 = 钉版 + v11「输入须转义、输出全转义」契约；喂转义 textContent + 每块单次
高亮（`.hljs` 跳重）即合规。

**② 数学 / 化学（KaTeX + `trust:false`）：**
1. **输入是文本、非 HTML。** carrier 经 marked 扩展 `escapeHtml` 转义 + DOMPurify 守门后落
   `<span class="math-tex">` 文本，`textContent` 取回原样 TeX 交 `katex.render` **解析 TeX、非
   HTML**。即便写 `<img onerror=…>`，只是 TeX 解析器眼里一段会报错的文本。
2. **`trust:false`（铰链，且为 KaTeX 默认）。** 禁 `\href`/`\url`/`\includegraphics` 及全部
   `\html*`（`\htmlClass`/`\htmlId`/`\htmlData`/`\htmlStyle`），令其渲成**错误色**而非生效 →
   恶意公式注入 `<a href=javascript:>` / HTML 属性的命令在产物里被禁、不存在。配置硬编码、前端
   无放宽旋钮。
3. **隔离铰链：逐公式独立 `katex.render`，无共享 `macros`。** 不传 `macros` → 每次 render 自带
   默认 `{}`，`\gdef`/`\newcommand` **连同气泡内都不跨公式泄漏**（比观澜 auto-render「每容器一份、
   页内 `\gdef` 可生效」隔离更强 —— 茶话室聊天场景无跨公式 preamble 需求，逐公式隔离更简更净）。
4. **产物注入当前 DOM、不再过 DOMPurify。** `trust:false` 下 KaTeX 产物仅其内置构建器生成的
   `<span class="…" style="…">` 与 MathML，**无活链接 / 无任意属性 / 无 `<script>`/事件处理器**；
   即便有漏网 inline `<script>`，CSP `script-src 'self'` 也禁其执行。信任铰链 = `trust:false`
   + 钉版 + 失败保留源码 + CSP 兜底。

**③ `marked → DOMPurify` 管线全程不破。** carrier 节点只是 `<span class="math-tex">转义文本
</span>`，过 DOMPurify(`USE_PROFILES.html`) 时 `span` + `class` 在白名单、文本已转义 →
原样保留、零绕过。代码块 `<pre><code class="language-X">` 同理。**DOMPurify 仍守一切原始 HTML
注入**（茶客写 `<script>` / `<img onerror>` 在 markdown 正文里 → marked 转义 + DOMPurify 剥，
与 P10 一致、不破）。

**④ 失败封闭。** 任一渲染器加载失败 / 单元异常 → 退回保留源（代码纯文本 / 数学 carrier 字面
TeX / KaTeX 错误色源码），**任何异常路径不产生未消毒注入、不空白**。

### 4.5 CSP 无需改动（验证项）

现有 CSP（`index.html:10`）已覆盖三类新资源，**P10.1 不动一行 CSP**：

| CSP 指令 | 现值 | P10.1 需求 | 是否需改 |
|---|---|---|---|
| `script-src` | `'self'` | 动态 `import()` katex/hljs（同源 `node_modules`） | 否（同 mermaid 已验证） |
| `style-src` | `'self' 'unsafe-inline'` | KaTeX 产物内联 `style` 属性 + `katex.min.css` 同源 | 否（`'unsafe-inline'` 已在，为 mermaid `<style>` 所需） |
| `default-src` | `'self'` | KaTeX woff2 字体（`@font-face` 同源拉取、无 CDN） | 否（`font-src` 回退 `default-src 'self'`） |
| `img-src` | `'self' data: blob:` | KaTeX / hljs 不用图 | 否 |

**残余风险与处置（保守表述）：** KaTeX/highlight.js 历史均有过 XSS CVE（KaTeX 多发于
`trust:true` 或旧版，highlight 多发于 HTML 透传 / 旧版）。本期不把二者输出当无条件可信，边界收
在：① **钉版**（`package.json` 钉 katex/highlight，升级走显式 PR 复核）；② 配置**硬编码**
（KaTeX `trust:false` + 无共享 macros；highlight 喂转义 textContent + 单次高亮）；③ **失败保留
源码**；④ **Electron CSP** 兜底（script-src 'self' 禁 inline/远程脚本执行）。

## 6. 决策记录

- **\[决策P10.1-1] 两运行时（KaTeX 家族 + highlight.js）走 npm 直接依赖 + 动态 `import()` 懒
  加载，与 mermaid 同骨架（非观澜的 vendored UMD + 注入 `<script>`）。** 茶话室渲染进程本就走
  ES module 直引 `node_modules`（`marked` / `dompurify` / `mermaid` 皆然），故沿用：① **非 CDN**
  —— electron-builder 打进 app、离线可用（KaTeX 字体经 `@font-face` 同源拉取）；② **无构建** ——
  用 dist 的 `.mjs` / `.min.css`，动态 `import()` 读 `mod.default`；③ **无 carrier / 无可高亮块
  零加载** —— `typesetMath` / `highlightCode` 先早退才付加载代价。**`katex` 已在 `node_modules`**
  （mermaid 0.16.47 传递依赖）—— 白捡运行时，仅需在 `package.json` 提为**直接依赖钉版**（防
  mermaid 依赖树变动带走它）；`highlight.js` 新增直接依赖。打包白名单按 mermaid 同款剔除多余
  dist（§9）。**退路**：若不接受第三方运行时，保持现状字面源码（决策P10.1-7 的 honest 回退本
  就常驻）。
- **\[决策P10.1-2] 数学 / 化学取 KaTeX —— `trust:false` 默认安全（白名单式单旗），且 katex 已
  随 mermaid 在树内含 mhchem contrib。** 同观澜 P4.14-2 的安全论证（KaTeX `trust:false` 是默认
  即开的单旗白名单、结构上消除整类不确定，优于 MathJax 全量包减法黑名单）；茶话室还白捡「katex
  已是 mermaid 传递依赖、`contrib/mhchem.mjs` 现成」。化学 `$\ce{…}$` **须在分隔符内**（mhchem
  是 math-mode 宏）；裸 `\ce{}` 按字面留存、不渲染。
- **\[决策P10.1-3]（茶话室核心，区别观澜）数学拾取 = marked 扩展在转义前封箱成 carrier，**
  **而非 marked 后在 DOM 上 auto-render 文本走查。** 茶话室 marked 的 CommonMark 反斜杠转义会
  在 KaTeX 看到 TeX 之前吃掉内部 `\,`/`\\`/`\{`/`\_`/`\%`/`\&` 与 `\(`/`\[` 分隔符本身（§1.2
  实测）。故 marked 扩展 tokenizer 命中即把整段 `$…$`/`$$…$$` 作单一 token 原样收走、不 re-lex
  内部 → TeX 字面零损耗。**只认 `$…$`/`$$…$$`**（不认 `\(…\)`/`\[…\]`，MVP）：后者被 marked
  降级、且与内置 escape tokenizer 抢位需谨慎，LLM 主流输出是 `$` 系。代价是 `$` 与字面美元号
  歧义（「$5 至 $10」），以 inline pandoc 风格正则收窄（开 `$` 后不接空白/数字、闭 `$` 前不接
  空白、闭 `$` 后不接数字）；其代价是数字开头的行内公式（`$2x$`）也被拒，honest 残留 —— 写
  `$$2x$$`（display 无此启发式）或以字母 / 命令开头规避，语法不通 `throwOnError:false` 退错误色。
  **display（`$$…$$`）故意走 inline-level tokenizer、非 block-level**：marked 的 block tokenizer
  只在行首触发，会漏掉句中 `$$…$$`；inline-level 两种位置都接（独占一行的 `$$…$$` 仍落 `<p>` 内一个
  `.math-display` carrier，KaTeX `displayMode` 经 `.katex-display{display:block}` 视觉成块，实测
  `<p><span class="math-tex math-display">…</span></p>` 结构合法）。真 block-level 标准化推后、非缺陷。
- **\[决策P10.1-4] KaTeX 在 DOMPurify 之后、live DOM 上渲，只在 message_end 调一次 ——**
  **不把 KaTeX HTML 塞进 `renderMarkdown` 过 DOMPurify、不在流式 delta 渲。** 两因：① DOMPurify
  (`USE_PROFILES.html`) 会剥 KaTeX 内联 `style` / MathML，破排版；② 流式每 delta 重渲
  `innerHTML`，parse-time 渲会在半截公式上反复跑 KaTeX（抛错 + 性能）。carrier 把「源在 markdown
  里」与「富渲延后」解耦，与 mermaid「carrier 在 markdown、富渲在 `enhanceContent`、只在全文到位
  时调」完全同构。carrier 只需 `span` + `class`（DOMPurify 天然放行），KaTeX 产物不再过 DOMPurify、
  靠 `trust:false` + CSP 自洽（§4）。
- **\[决策P10.1-5] 本期安全 / 隔离边界 = marked carrier 转义（escapeHtml）+ DOMPurify 守 carrier
  + KaTeX `trust:false`（默认安全、硬编码、无放宽旋钮）+ 逐公式独立 `katex.render`（无共享
  macros、隔离强于观澜）+ highlight v11 转义契约 + 失败保留源码 + Electron CSP 兜底；不承诺产物
  绝对可信。** 见 §4。残余 CVE 以钉版 + 显式升级 PR 复核处置。**验证策略**：源码断言（`trust:false`
  在、未把共享 `macros` 塞进 `KATEX_OPTS`、调用以 `{...KATEX_OPTS, displayMode}` 展开）是廉价
  守门；真正生效与否走 §7 Electron 手测。

## 8. 不变量增量

CLAUDE.md「聊天界面渲染（P10）」section 新增以下条目（与 §97 mermaid 不变量同位）：

- **数学 / 化学走 marked 扩展「转义前封箱」+ KaTeX live-DOM 延后渲，不走 auto-render 文本走查**
  （P10.1 §3.1 / §1.2）。茶话室客户端 `marked → DOMPurify` 管线里，marked 的 CommonMark 反斜杠
  转义会在 KaTeX 看到 TeX 前吃掉内部 `\,`/`\\`/`\{`/`\_`/`\%`/`\&` 与 `\(`/`\[` 分隔符 ——
  故必须用 marked 行内扩展（`mathDisplay`/`mathInline`，display 先注册长匹配优先）把整段
  `$…$`/`$$…$$` 作单一 token 原样收走、不 re-lex 内部，renderer 产 carrier
  `<span class="math-tex math-inline|math-display">escapeHtml(TeX)</span>`。**只认 `$…$`/`$$…$$`**
  （不认 `\(`/`\[`）。`$` 货币歧义以 inline pandoc 风格正则收窄（开 `$` 后不接空白/数字、闭 `$`
  前不接空白、闭 `$` 后不接数字）；honest 残留：数字开头行内公式（`$2x$`）也被拒，应写 `$$…$$`。
- **KaTeX 在 DOMPurify 之后、live DOM 上渲，只在 message_end 调一次，逐公式独立 render**
  （P10.1 §3.2 / §4）。**不**把 KaTeX HTML 塞进 `renderMarkdown` 过 DOMPurify（会剥内联 style /
  MathML 破排版）、**不**在流式 `appendDelta` 渲（半截公式抛错闪烁 + 性能）。`typesetMath` 扫
  `span.math-tex:not(.math-done)`、`katex.render(textContent, el, {...KATEX_OPTS, displayMode})`
  就地替换、标 `.math-done` 幂等。`KATEX_OPTS` 硬编码 `trust:false`（默认安全、禁
  `\href`/`\url`/`\includegraphics`/`\html*`）+ `throwOnError:false`（语法错退错误色源码）+
  `strict:"ignore"`；**不传 `macros`** → 每次 render 自带默认 `{}`、`\gdef`/`\newcommand` 连
  气泡内都不跨公式泄漏（隔离强于观澜 auto-render「每容器一份」）。产物不再过 DOMPurify、靠
  `trust:false` + 钉版 + Electron CSP 兜底。
- **代码高亮 highlight.js v11 喂转义 textContent、单块单次、跳 mermaid / 已高亮 / 未注册语言**
  （P10.1 §3.3）。`highlightCode` 扫 `pre>code[class*="language-"]`，跳 `language-mermaid`（归
  mermaid）/ `.hljs`（v11 重复高亮告警）/ `getLanguage` 为空（未注册 → 保纯文本、不猜不报错）；
  `hljs.highlightElement(code)` 就地高亮。v11 读 `.textContent`（已转义源）、产物仅
  `<span class="hljs-*">转义文本</span>`、移除 HTML 透传 → 输入不当 HTML。懒加载
  `import("@highlightjs/cdn-assets/es/highlight.min.js")`（自包含浏览器 ESM；**不能用 `highlight.js`
  包的 es/* CJS shim**，沙箱渲染进程无 CJS 互操作会抛），失败 / 单块异常保留纯文本代码。
- **`enhanceContent` 泛化 `renderMermaidIn` 单钩子，挂原三注入点、随重绘重增强**（P10.1 §3.4）。
  `enhanceContent = renderMermaidIn + highlightCode + typesetMath`（区域不相交、各自幂等、均
  fire-and-forget）；三处 `renderGuestText`（:303）/ `endStreamingMessage`（:278/:284）/

- **P10.1 纯前端：后端零改、无新增协议 / 不 bump `schema_version`、CLI 不渲染、CSP 不改**
