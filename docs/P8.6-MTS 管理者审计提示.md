## 1. 背景：自主推进的两个失效模式

MTS 让 manager 在预算内自主推进（P8.3/P8.4）。两个失效在「自主」放大后变明显，而既有
`<managed_session>` 块（P8.4 §5 的 5 条 bullet）都没覆盖：

| 失效 | 表现 | 既有块为何挡不住 |
|---|---|---|
| **目标缩水** | manager 把多步 Goal 收敛成"最容易判完成"的子集，对着子集 `task_propose_status("done")` | 第 ⑤ 条只说「Goal 达成就 propose done」，没定义"达成"=全量 scope 逐条核验 |
| **过早放弃** | manager 一遇阻碍就 `task_propose_status("blocked")`，把一次性挫折升级成「任务阻塞」 | 块完全没提 blocked；第 ④ 条只覆盖「没下一步 → 待机」，没区分「待机一轮」与「真阻塞」 |

两者都是 codex `/goal` 重 prompt-engineering 治过的点：`continuation.md` 的核心目的就是
**对抗 agent 把目标缩成最容易通过的子任务**（被借鉴文档 §4），`spec.rs` 的 `blocked` 工具
描述要求「同一阻塞连续 ≥3 个 goal 回合」才合法（§3 / §11.1-E.1）。ChaHua 把这两条**降维
成 prompt 文案**搬进 `<managed_session>` 块即可 —— 不需要 codex 的工具层 / 状态机层实现。

**为什么是 prompt 而非工具/状态机**（沿用 P8.4 §5「prompt 改对比工具改对成本低」）：两条
都是"软纪律"，硬塞进 `task_propose_status` 会要它读历史回合数判 3+、要它解析 Goal 子集 ——
脆弱且越权。codex 自己也只在工具描述里写、不在实现里强制。

## 2. 改动：第 ④ / ⑤ 条 bullet 扩文案

`render_managed_session_block` 返回串里**只改两行 bullet**（其余 4 行 + 头尾 + budget 行 +
语言锚点一字不动）：

```text
# 第 ④ 条（before，P8.4）
- No next step (need to read more, need user input, stuck)? Just finish your turn —
  the session idles and waits for the user; it does NOT end because you did not
  delegate this round.

# 第 ④ 条（after，P8.6 —— 追加 blocked 防过早放弃）
- No next step (need to read more, need user input, stuck)? Just finish your turn —
  the session idles and waits for the user; it does NOT end because you did not
  delegate this round. Do NOT task_propose_status("blocked") on the first obstacle —
  only mark blocked when the SAME blocker has recurred across 3+ consecutive review
  rounds; a one-off setback is an idle round, not a blocked goal.
```

```text
# 第 ⑤ 条（before，P8.4）
- Goal met? Call task_propose_status("done") to wrap up (the proposal goes to the
  user for confirmation, not auto-applied) and stop delegating.

# 第 ⑤ 条（after，P8.6 —— 前置反目标缩水审计）
- Goal met only after verifying the FULL task scope requirement-by-requirement —
  do NOT shrink the goal to an easier-to-pass subset just because it is closer to
  done. Only then call task_propose_status("done") to wrap up (the proposal goes to
  the user for confirmation, not auto-applied) and stop delegating.
```

**承重子串保留**：第 ④ 条保 `No next step` / `Just finish your turn` / `idles` /
`does NOT end`（既有断言）；第 ⑤ 条保 `task_propose_status("done")` /
`the user for confirmation, not auto-applied` / `stop delegating`（P8.4 §2「propose done →
用户采纳 → task_closed」契约靠这些子串）。两条审计是**追加 / 前置**，不替换。

  `tests/test_mts_spawn_boundary.py` 对「第 ③ 条」spawn 的引用断言不动 —— 两条均未被本阶段
  触碰，回归须同时仍绿。

  工具 schema；语言锚点 `Always reply in the same language…` 保留。
- **`blocked` 仍是非终结态**：本阶段只加"何时**该**提议 blocked"的 prompt 节流，不改
  `blocked` 落库后是否终结 MTS —— 采纳 blocked 仍走 `update_task`、MTS 仍 dormant（P8.5
  §4.3 第 2 点的联动是另一回事，未做）。
- **审计是 prompt 级软纪律，不是硬约束**：与 codex 同口径（被借鉴文档 §3）。模型若仍违反
  （首次就 propose blocked / 对子集 propose done），既有路径照常 —— propose 仍走用户采纳卡，
  用户是最终闸门。P8.6 降低概率，不做强制拦截。
