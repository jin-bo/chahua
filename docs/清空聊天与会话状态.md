# 清空聊天与会话状态

本文记录一次排查结论：在「清空聊天」之后，茶客仍可能表现出记得清空前做过的事。这不一定来自 `.agentao/memory.db`。

## 当前清空范围

当前 `clear_room` 走 `ChahuaServer._clear_room()`，实际调用 `Orchestrator.reset_room()`。它只清空房间公共状态：

- `transcript.jsonl`
- `summary.jsonl`
- `cursor.json`
- 编排器运行时计数器，例如冷却、连续 AI 轮数

它不会清空：

- 当前进程中的 `RoomSession`
- 已构造的 `TeaGuest`
- `TeaGuest` 内部的 `Agentao` 实例
- 茶客 `working_directory`
- 茶客 `.agentao/`
- 房间 `share/`

代码注释里也明确写了这个语义：茶客实例 / agentao session 不动，茶客在房间公共记录里看不到之前发生过什么，但自身实例仍保留。

## 为什么没有 memory.db 也会“记得”

一次实际案例：

- Yvonne 的 `memory.db` 中 `memories`、`session_summaries`、`memory_review_queue` 都为空。
- 清空后询问 `@Yvonne share 目录下有哪些文件`，Yvonne 仍回答出 `share/` 下的五个文件，并说前三个已经审过。

这个现象有两部分来源：

1. `share/` 是仍然存在的房间共享目录。Yvonne 的工作目录里有 `share` 软链接指向房间共享目录，清空聊天不会删除这些文件，所以茶客可以重新读取目录内容。
2. “前三个已经审过”不是来自 `memory.db` 的长期记忆，而更可能来自当前 sidecar 进程中仍存活的 `Agentao` 会话状态。清空聊天没有销毁并重建 `RoomSession`，所以同一个 Yvonne 实例仍在进程内。

此外，一旦清空后 Yvonne 把这句话重新说进房间，新的 `transcript.jsonl` 就会再次包含这段内容。之后再追问时，茶客也可以从新的房间 transcript 里看到它。

## RoomSession 的持久化边界

`RoomSession` 本身不是一个落盘文件，而是运行时对象。它从房间目录装配：

```text
rooms/<room-id>/room.toml
rooms/<room-id>/transcript.jsonl
rooms/<room-id>/summary.jsonl
rooms/<room-id>/cursor.json
rooms/<room-id>/share/
rooms/<room-id>/tasks/
rooms/<room-id>/guests/<name>/
```

茶客私有数据位于：

```text
rooms/<room-id>/guests/<name>/.agentao/
```

如果茶客配置为 `isolation = "global"`，则工作目录会改到用户数据根下的全局 `guests/<name>/`，不随单个房间删除。

## 如果要做“真正失忆”的清空

需要定义一个比当前「清空聊天」更强的操作，例如「重置房间会话」或「清空并重建茶客」。候选语义：

- 先取消当前 in-flight turn。
- 关闭当前 `RoomSession`，释放所有 `TeaGuest/Agentao` 实例。
- 清空 `transcript.jsonl`、`summary.jsonl`、`cursor.json`。
- 重新 `build_room_session()`，让所有茶客以新实例进入房间。
- 是否清空 `guests/<name>/.agentao/`、`workspace/`、`share/` 需要独立开关，因为这些目录包含用户主动上传或茶客产出的文件。

推荐把 UI 文案区分为：

- 「清空聊天」：只清公共聊天记录、摘要和游标，保留茶客实例、工作区、共享文件。
- 「重置会话」：重建 `RoomSession/TeaGuest/Agentao`，清掉进程内会话状态。
- 「清空房间数据」：危险操作，进一步删除工作区、`.agentao/` 或 `share/`，需要明确确认。
