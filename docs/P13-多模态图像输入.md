# P13：多模态图像输入 —— 用户发图，视觉茶客看像素，非视觉茶客退化文本引用

> 用户发图（**C1 走现有文件选择路径即可**，贴 / 拖 / 缩略图后置增强），**视觉能力的茶客模型直接看到像素**；**不支持视觉的茶客模型自动退化为文本引用**（逐茶客独立，因为每个茶客包自己的 model）。打分阶段不吃图、保持纯文本。

## Summary

现状：用户上传的文件（含图片）只以 `<./share/<name>>` 文本标记进入 prompt，视觉模型也「看不见」像素。

P13 让**本轮触发用户消息**里的图片，在茶客 `speak()` 时作为 OpenAI `image_url` content blocks 附给该茶客的 model。**降级零自研** —— agentao（≥0.4.8）已实现逐模型的 reactive「图→文本引用」回退：模型拒图报错 → `_is_image_unsupported()` 识别 → 整条多模态消息换成文本引用 + 解释 → 重试。因每个 `TeaGuest` 包独立 `Agentao`（各自 LLMSpec/model），「视觉茶客看图、非视觉茶客退化」天然逐茶客发生，chahua **不做能力探测表**。

**视觉附图是纯瞬态运行态，不持久化**：因附图范围严格 = 本轮触发用户消息，`images_rel` 作为 Python 形参沿当前 turn 同步透传（`submit_user_message → _run_ai_chain → let_speak → speak`），用完即弃。**不改 `Message` dataclass、不改 transcript schema、不改 envelope**。`<./share/<name>>` 文本标记照旧落 transcript（非视觉茶客 + 打分模型 + 历史轮次靠它感知「这里有张图」），base64 只在 speak 时从 `share/` 懒读现传。

## 承重不变量

- **降级是 agentao 的职责，不在 chahua 复制**。chahua 只负责把 `images=[{data, mimeType, _source}]` 传进 `arun()`；模型拒图后的「换成文本引用并重试」由 agentao `_runner.py` / `_retry.py` 完成。chahua 不写 `_is_image_unsupported` 同义物、不维护 per-provider 视觉能力表。**Why**：能力探测跨 provider 不可靠；reactive 回退是 agentao 单一真理源，逐茶客 model 各自生效。
- **视觉附图纯瞬态，不持久化、不改任何 schema**。`images_rel` 是 Python 形参，沿当前 turn 同步透传后即弃；**不动 `Message` dataclass / transcript / envelope**。**Why**：附图范围严格 = 本轮触发用户消息（见下），同步透传足够；给一个非持久能力引入持久模型字段是过度设计。reconnect / 历史重建走文本标记即可。
- **base64 懒读不入库**。图片 bytes 只在 `speak()` 时从 `share/` 实路径现读现传 `arun`，**绝不写进 `transcript.jsonl` / 任何 envelope**。transcript 只有 `<./share/..>` 文本标记。**Why**：契合「图片预览懒拉」「大 blob 不落 transcript」「API key 永不进 envelope」同一精神 —— transcript 是长期可信文本日志，不堆兆级 base64。
- **文本标记是普适视图，视觉附图是增量**。`<./share/<name>>` 行照旧追加进 message text、落 transcript、进 prompt。视觉附图只对支持的茶客额外可见。**Why**：非视觉茶客、打分模型、历史轮次的茶客都只能靠文本标记感知图存在；删掉它们会让降级路径丢上下文。
- **打分永不吃图**。`scoring.py` 路径不变，transcript 里图仍是 `<./share/..>` 文本。**Why**：省视觉 token、契合「打分输入不可信 / 严格 JSON」—— 打分只需知道「有张图」，不需看像素。
- **附图范围 = 本轮触发用户消息，且只流入 `_run_ai_chain` 一条路径**。`submit_user_message` 现有流程是「先 `run_pending_handoff`（pre-drain）→ `_run_ai_chain` → re-drain」（`orchestrator.py:76-97`）。C1 **只把 `images_rel` 透传进 `_run_ai_chain`**；pre-drain / re-drain / dormant MTS kickoff / 所有 handoff / MTS 路径**只看 `<./share/...>` 文本标记、不看像素**。**Why**：① 不扩 `run_pending_handoff` 接口，契合「最小后端线」；② 这些路径本就是茶客 / 调度触发，无「本轮用户图」语义；③ 有界可预测、撞不上 16 图 / 20MB 上限、匹配「回应刚分享的图」的直觉。历史图对后续 turn 的茶客同样退回文本引用。
- **图类型按扩展名白名单识别，resolve 时映射 MIME**。线协议无 MIME（`upload_file` 回 `rel/name/size/original`，`user_message.files` 只有 rel）—— 不扩协议、不做内容嗅探。`_inbound_user_message` 按扩展名白名单 `{png, jpg, jpeg, gif, webp}` 从 `files` 筛出 `images_rel`；`resolve_images` 用扩展名→MIME 映射给 agentao 填 `mimeType`。白名单与现有 preview 内嵌白名单一致（SVG 不作视觉输入，可内嵌 `<script>`）。
- **`_source` 直接用 rel**。rel 全程已是 `share/x.png` 形态（不要再前缀 `share/`，否则成 `share/share/x.png`）。让 agentao 降级文本输出 `- share/x.png (image/png)` 与 prompt 里已有的 `<./share/x.png>` 标记口径一致。
- **限额对齐 agentao**。`MAX_IMAGE_BYTES = 20MB` / `MAX_IMAGES_PER_TURN = 16` 直接 `from agentao.media_limits import ...`，不在 chahua 另立常量漂移。
- **`chahua/image_input.py` 轻量 helper 模块，两函数职责分明**。① `_normalize_share_image_rel(rel) -> str | None`（**纯字符串校验、无 IO**）：要求 `share/` 前缀、扩展名在白名单、路径段非 `""` / `.` / `..`、无绝对路径 / 反斜杠；任一不满足返回 `None`（inbound 筛图 + resolve 双点复用此校验）。② `resolve_images(share_dir: Optional[Path], rels) -> list[dict]`（**模块函数、负责 IO** —— 读盘 / 查 size / base64 / WARN）：`TeaGuest.speak` 调 `resolve_images(self._share_dir, images_rel)`，**不是 TeaGuest method**。**`share_dir is None` 且 `rels` 非空 → 返回 `[]` + WARN 一次**（裸构 `TeaGuest` / 异常装配的兼容路径，视觉输入退化为无图，绝不炸 speak）—— 同 `active_guest_names is None` 跳过的口径。**不复用 `_attach_files_to_text` 的围栏** —— 它更宽（不要求 `share/` 前缀、不拒空段 / `.` 段），不够 P13 读盘安全。住独立模块而非 `guest.py` 私有 —— server inbound 与 guest 跨层共用，小模块是最小共享面，不让 server import guest。
- **读盘前先剥 `share/` 前缀再拼，绝不 `self._share_dir / rel`**。`rel` 是 canonical 形态 `share/x.png`，而 `self._share_dir` 已是 `<room>/share/` —— 直接拼会成 `<room>/share/share/x.png`。落点写死：`sub = rel.removeprefix("share/")`（normalize 已保证前缀存在）→ `target = (self._share_dir / sub).resolve()`。
- **读盘点必做 symlink 逃逸检查，与 `download_file` 同口径**。段形校验拦不住「`share/x.png` 本身是指向房间外的符号链接」（且 chahua 的 share 本就是软链接拼装的）。`resolve_images` 读字节前：`target = (share_dir / sub).resolve()` → `target.relative_to(share_dir.resolve())`（**两侧都 `resolve()`**，因 share_dir 经软链接到达）→ 失败即跳过该图。照搬 `server_inbound_io.py:341-352` 的 `resolve()` + `relative_to` 口径。**Why**：纯段形校验是字符串层防穿越，symlink 逃逸是文件系统层防穿越，两层都要 —— 这是读盘安全底线不是过设计。

## 数据流（P13 后）

```
前端选图  →  upload_file 存 share/x.png（成功后 mark_share_seen）  →  user_message{text, files:["share/x.png"]}
server._inbound_user_message:
   text' = _attach_files_to_text(text, files)                       # 仍含 <./share/x.png> 标记
   images_rel = tuple(filter(None, map(_normalize_share_image_rel, files)))  # → ("share/x.png",)
   submit_user_message(text', images_rel=images_rel)
orchestrator: room.append("user", text')                   # transcript 只存文本(含标记),无 images 字段
   _run_ai_chain → images_rel 只给第一周期（回应用户那批）的 let_speak（AI 接力周期退文本，用完即弃）
let_speak → speak(ctx, images_rel=("share/x.png",))
guest.speak:
   resolved = resolve_images(self._share_dir, images_rel)   # normalize → removeprefix share/ → share_dir/x.png resolve 围栏 + 读 + base64 + ext→mime + 限额
   arun(ctx, images=resolved)
     ├─ 视觉模型 → 看到像素
     └─ 非视觉模型 → agentao 拒图 → 换 "- share/x.png (image/png)" 文本引用 → 重试
打分: scoring 仍用纯文本 transcript(含 <./share/x.png> 标记) —— 不吃图
```

## 边界与已知交互

- **artifact_detector：无需新增处理**。`server_inbound_io.py::_upload_file` 成功后已调 `orchestrator.mark_share_seen(rel)`（`server_inbound_io.py:148`，P10.2 引入），用户上传到 `share/` 不会被下一轮当茶客产物重发 `room_artifact_added`。P13 沿用，不列为风险 / 核对项。
- **debug 取证**：`capture_prompts` 落 `speak_prompt`（纯文本 ctx）。base64 不进 debug（懒读发生在 emit `MESSAGE_START` 之后的 `arun` 内）。可选：在 debug 里记 `images_rel` 列表（rel-only）便于回放，不记 bytes。
- **历史 / 切房**：`room_history` 重建只回放 transcript 文本（含标记）；图按需 preview 拉取走既有 `download_file purpose=preview` 路径，与 P13 视觉输入正交。
- **MTS / handoff / pre-drain / re-drain / bg run**：`images_rel` 只进 `_run_ai_chain`（见不变量）。`submit_user_message` 里先跑的 `run_pending_handoff`、dormant MTS kickoff、chain 后 re-drain，以及一切 handoff / MTS / bg run 路径，均**只看 `<./share/...>` 文本标记、不接像素** —— `run_pending_handoff` 接口不改。bg run 若未来要支持图，另开增量。
