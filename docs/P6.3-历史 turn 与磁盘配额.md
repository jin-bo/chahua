# P6.3 历史 turn 列表 + 磁盘 rotation

> 目标：把 P6.1 / P6.2 落到盘上的 `rooms/<id>/debug/` 拉到前端 —— 让"打开窗口前发生的 turn"
> 也能在调试抽屉里翻；同时给 `debug/` 加一个有上限的"老 turn 自动清"机制，避免长会话
> 房间盘上慢慢堆 GB。

**前置**：P6.1 / P6.2 已落地（recorder 落盘 + 实时抽屉）。本节**不动 P6.1 落盘 schema**
（仅在 jsonl 行末追了 1 个 `closed=true|absent` 语义字段，未知字段忽略口径吃下），
**不动 P6.2 实时数据通路**（in-memory `turns` Map 仍是实时流的权威；历史只是补一段
"开窗前"的视野）。

---

## 1. 问题

P6.2 完成后，调试抽屉**只看本次 ws 连接之后**发生的 turn —— ws 断线 / 切房 /
F5 刷新都会清空 `debug_panel.turns` Map。**最需要排查的场景偏偏在窗口之外**：

| 场景 | 当前 P6.2 表现 | 缺口 |
|---|---|---|
| 半夜 AI 接力 100 轮，第二天开窗想看"凌晨 3 点那轮为啥没人接话" | 抽屉空白；只能 `cat rooms/<id>/debug/turns.jsonl` | 取证落盘了但 UI 看不到 |
| 切到另一房间再切回来 | `reset()` 后回到本会话起点 | 切房之前的 turn 不可见 |
| Electron 崩溃重启 | 重连后只看到重启后发生的 turn | 崩前的 prompt / 工具调用看不到（落盘还在，UI 接不上） |
| 长跑 1 个月的房间 | `debug/turns.jsonl` 数 MB、`prompts/` 几千文件 | 没有自动清理；用户得手动 `rm -rf` |

P6.1 把数据落得很完整（per-turn 一行 jsonl + per-turn prompt 子目录），
**就差一个把它流回前端的协议**。

## 2. 拆两个子项

| 子项 | 范围 | 顺序 |
|---|---|---|
| **P6.3.A：历史 turn 列表** | `turns_index` 进 `room_history` / `FETCH_TURN_DETAIL` inbound / `TURN_DETAIL` envelope / 抽屉索引行点击即拉详情，详情走既有 `evictOldest` | 先做 |
| **P6.3.B：磁盘 rotation** | `[debug]` 加 `max_mb` 字段 / 启动时全量 + flush 节流（每 50 次 flush 或 ≥ 60 秒）检查 / 按 `turn_id` 倒序保最新 N MB | 后做 |

两个子项**互相独立**：
- 没 rotation 也能跑 A —— 上限就是用户手动清。
- 没 A 也能跑 B —— rotation 只动盘，不动协议。

但 B 影响 A 的"最老一帧从哪里开始"：rotation 把老 turn 删掉后，索引也得跟着剪。所以
**B 落地时**要复用 A 的 `turns_index` 加载入口，确保 UI 不会请求一个已被 rotation 删
掉的 `turn_id`（请求到了也只 404 不崩，下面详）。

---

## P6.3.A：历史 turn 列表

### 3. 数据流

```
ws 连上 / 切房 / 刷新
    ↓
emit_room_snapshot(server, sink)
    ├── emit_room_info
    ├── emit_room_history          ← data 多 turns_index: [{turn_id, ts_ms, ...}]
    └── _emit_task_info

[用户打开调试抽屉，点击某条历史索引行]
    ↓
debug_panel.js 发 FETCH_TURN_DETAIL { turn_id: "turn_xxx" }
    ↓
ChahuaServer._inbound_fetch_turn_detail
    ├── 读 rooms/<id>/debug/turns.jsonl 找该 turn 行
    ├── 按 prompt_file / speak_prompt_file 字段读旁路 .txt
    └── emit TURN_DETAIL { turn: {…完整一行…}, prompts: {<rel>: text} }
        ↓
debug_panel.js 把这条 turn 插进 turns Map（与实时流共用同一 Map），把原索引行 DOM 内容
替换为详情视图；详情走既有 evictOldest，被 evict 时**还原回轻量索引行**（不删 DOM 节点，
保留点击复拉的入口）。
```

**关键决定**：
- **历史 turn 共用实时流的 `turns` Map** + **统一 `evictOldest`**：UI 不分"实时区 /
  历史区"两个列表 —— 实时 turn 渲在顶，历史索引行紧随其后，按 ts_ms 倒序。
  `turns` Map 受 `MAX_TURNS_IN_MEMORY=50` 上限管理；实时与历史详情同一份预算。
  历史详情有 `fromHistory=true` + 缓存原 `indexEntry`，evict 时不删 DOM、改为
  "还原索引行"（详见 §6.1）。
- **历史索引常驻不参与 evict**：1000 条索引行轻量 DOM（每行 ~200B），常驻不会膨胀。
- **`turns_index` 只下行轻量字段**：避免 ws 单帧 1MB 警戒；详情 + prompt 走 inbound 拉。
- **prompt 文件随详情一帧打包回传**：避免前端再开一轮 inbound 拉 N 个 .txt。一份完整
  turn 的 scoring + speak prompt 通常 20-50KB，单帧装得下。

### 4. wire 协议

#### 4.1 `room_history.data` 多加 `turns_index`

```json
{
  "type": "room_history",
  "data": {
    "messages": [...],            // 原有 transcript 回放，不动
    "turns_index": [              // 新增；不变量"未知字段忽略" → 老前端不感知
      {
        "turn_id": "turn_<hex>",
        "ts_ms": 1731912345678,
        "task_id": "task_<hex>",
        "trigger_kind": "user_msg",
        "scoring_path": "scoring",
        "winners": ["Alice"],
        "n_messages": 1
      },
      ...
    ]
  }
}
```

**字段口径**：
- 倒序（最新在前）—— UI 自下而上懒拉时直接按数组顺序去重。
- `n_messages`：用于在索引面板上显示"该 turn 几条消息发了出来"，给"全员低分的空 turn"
  一个明显的视觉提示（`winners=[]` 且 `n_messages=0`）。
- **不放 `scoring.scorables` / `cooled` / 各 guest 分数**：让索引保持精简（每条 ≤ 200B），
  详情拉时再带。

**`turns_index` 的来源**：服务端起房间时调 `TurnRecorder.load_index() -> list[dict]`
（读 `debug/turns.jsonl`，复用 `read_jsonl_skip_bad`，**跳坏行 + 投影出索引字段**）。
这个调用同 `Room` 加载 transcript 一样发生在 `build_room_session`，不动 ws 路径热路径。

**`debug.enabled=False`** 时 `turns_index` 字段**整字段缺省**（与 piggyback 口径同款 ——
不下发 `"turns_index": []`，避免前端误认为"开着但确实空"）。

#### 4.2 inbound：`FETCH_TURN_DETAIL`

```json
{
  "type": "fetch_turn_detail",
  "turn_id": "turn_<hex>"
}
```

字段白名单**严格**（同 task inbound 口径）：
- `type` 必需且 == `"fetch_turn_detail"`。
- `turn_id` 必需且 `^turn_[0-9a-f]+$`（regex 强校验 —— 这是路径片段，要拒穿越
  `..` / `/` —— 后端 `prompts/<turn_id>/*` 直接拼字符串）。
- 未知字段 → NOTICE error + 丢帧。

#### 4.3 outbound：`TURN_DETAIL` envelope

新 `ChahuaEventType.TURN_DETAIL = "turn_detail"`。

```json
{
  "type": "turn_detail",
  "turn_id": "turn_<hex>",       // envelope 顶层字段，与实时 envelope 同款
  "data": {
    "found": true,
    "turn": {
      "schema_version": 1,
      "turn_id": "turn_xxx",
      "ts_ms": 1731912345678,
      "task_id": "task_xxx",
      "trigger": {"kind": "user_msg", "ref_seq": 42},
      "scoring": {
        "threshold": 0.65,
        "scorables": [...],
        "cooled": [...],
        "results": [
          {"guest": "Alice", "score": 0.72, "kind": "scored", "raw": "...",
           "prompt_file": "prompts/turn_xxx/scoring_Alice.txt"},
          ...
        ],
        "winners": ["Alice"]
      },
      "scoring_path": "scoring",
      "messages": [
        {"message_id": "msg_xxx", "guest": "Alice",
         "speak_prompt_file": "prompts/turn_xxx/speak_msg_xxx.txt",
         "status": "ok", "seq": 43,
         "tool_calls": [...], "artifact_paths": [...]}
      ]
    },
    "prompts": {
      "prompts/turn_xxx/scoring_Alice.txt": "<scoring prompt 全文>",
      "prompts/turn_xxx/speak_msg_xxx.txt": "<speak prompt 全文>"
    }
  }
}
```

**`found=false` 路径**：`turn_id` 在 `turns.jsonl` 没扫到（被 rotation 清了 / 写盘失败 /
前端拿了过期索引）→ `data: {"found": false}`，前端把索引里这条标灰并删除占位。
**不**算 ERROR —— 这是预期场景（rotation 与索引下发存在窗口），用 NOTICE 抖一下用户
体验反而恼人。

**`prompts` 字段口径**：
- `capture_prompts=False` 时 jsonl 里没有 `prompt_file` / `speak_prompt_file` →
  `prompts` 为 `{}`（不缺省整字段 —— 让前端代码无需双重判 "字段在不在 + 字典空不空"）。
- 任意 prompt 文件读失败（被 rotation 删 / 权限问题）→ 该 key 缺省，**不放空串**
  （与 piggyback 不变量"严格 enabled && capture_prompts 双开才出现"同口径）；前端
  按 `prompts[rel] === undefined` 渲"prompt 文件已不可用"提示。
- 全部 prompt 文件读失败 → `prompts: {}`，UI 仍能展开看 scoring 分数 / 工具调用 / 产物
  路径（jsonl 行内字段都在）。

### 5. 后端实现

#### 5.1 `chahua/debug_recorder.py` 加加载入口

```python
class TurnRecorder:
    ...

    def load_index(self, *, limit: Optional[int] = None) -> list[dict]:
        """读 ``debug/turns.jsonl`` 投影成 turns_index。

        - ``enabled=False`` → 返 ``[]``（room_history 下发时调用方据此整字段缺省）。
        - 跳坏行（复用 ``_persist.read_jsonl_skip_bad``）。
        - ``limit=None`` → 全扫返全部（**rotation 必须用这条**：截断要看到完整老 turn
          序列，否则 limit 之外的更老 turn 永远删不到，jsonl 仍超 cap）。
          ``limit=N`` → 内部 ``deque(maxlen=N)`` + 末尾反转返最新 N 条（room_history
          下发时用 ``limit=1000``）。
        - 倒序（最新在前），O(n) 扫一遍。
        """

    def load_turn(
        self, turn_id: str
    ) -> tuple[Optional[dict], dict[str, str]]:
        """按 ``turn_id`` 查 jsonl 行 + 读关联 prompt 文件。

        返回 ``(turn_dict | None, {rel: text})``。

        - **顺序扫**而非建索引：单房间 ``turns.jsonl`` 撑死几千行，每次 fetch 都 ≤ 50ms；
          建内存索引 = 进程驻留 N MB，rotation 与重建 / 失效复杂度都不值。
        - **找到一条立即停**：jsonl 单 ``turn_id`` 不会重复（理论上）；若重复取第一条
          + WARN（边界场景：手工编辑 / fsck）。
        - prompt 文件按 jsonl 行内字段查（``scoring[].prompt_file`` /
          ``messages[].speak_prompt_file``），单文件读失败时**整条 key 缺**而非空串
          （与 ``prompts`` 字段不变量对齐）；任意路径校验 ``resolve().is_relative_to(debug_dir)``
          —— 仅"jsonl 自己写下来的字段"也防一手（攻击模型：用户编辑 turns.jsonl 塞
          ``"prompt_file": "../../.env"``）。校验失败 → WARN 跳过。
        """
```

**为什么用顺序扫，不建内存索引**：rotation 后老 turn 物理消失，建索引就得加失效逻辑；
单文件几千行 grep 都比 dict lookup 大不到哪去；且 fetch 是用户主动操作（点滚动 /
点列表项），不在 100ms hot path。**未来 turns.jsonl 真撑到几万行**才考虑建 sidecar
索引文件（`turns.idx`），P6.3 不预投资。

#### 5.2 `chahua/server_room_snapshot.py::emit_room_history`

```python
def emit_room_history(server: "ChahuaServer", sink: EnvelopeSink) -> None:
    msgs = server._session.room.messages_since(0)
    data: dict[str, Any] = {"messages": [m.to_jsonl_dict() for m in msgs]}
    # debug 开启时附 turns_index；关闭时整字段缺省（不下发空数组）。
    recorder = server._session.recorder
    if recorder.enabled:
        idx = recorder.load_index(limit=TURNS_INDEX_HARD_CAP)  # 比如 1000
        if idx:
            data["turns_index"] = idx
    sink(ChahuaEnvelope(..., data=data))
```

`TURNS_INDEX_HARD_CAP=1000`（**索引硬上限**，与 rotation 上限独立）—— 让单帧 ws 不超过
~300KB（1000 × 300B/条）。盘上有 1500 条时只下最新 1000 条；用户翻到底要看更老的，
P6.3 不做（用户已能从盘上 grep），下一段"未来扩展"留。

#### 5.3 `chahua/server.py`：注册 inbound

按既有 `_INBOUND_ROUTES` 风格在 `ChahuaServer` 自身加一个核心 inbound（与 cancel /
switch_room 同级，不进 admin / task / io / settings 子 slot —— 它**不归任何 slot**，
是"debug 取证"独立通路）。

```python
INBOUND_FETCH_TURN_DETAIL = "fetch_turn_detail"

_INBOUND_ROUTES: dict[str, str] = {
    INBOUND_CANCEL: "_inbound_cancel",
    INBOUND_SWITCH_ROOM: "_inbound_switch_room",
    INBOUND_CLEAR_ROOM: "_inbound_clear_room",
    INBOUND_USER_MESSAGE: "_inbound_user_message",
    INBOUND_FETCH_TURN_DETAIL: "_inbound_fetch_turn_detail",  # 新增
    ...
}
```

handler 骨架（与既有 inbound 同款 try/except 包到底 / NOTICE error 出口）：

```python
_TURN_ID_RE = re.compile(r"^turn_[0-9a-f]+$")

async def _inbound_fetch_turn_detail(
    self, payload: dict, sink: EnvelopeSink
) -> None:
    check_keys_whitelist(payload, {"type", "turn_id"}, sink, self._emit_notice)
    turn_id = require_str(payload, "turn_id", sink, self._emit_notice)
    if turn_id is None:
        return
    if not _TURN_ID_RE.fullmatch(turn_id):
        self._emit_notice(sink, level=NOTICE_LEVEL_ERROR,
                          text=f"非法 turn_id: {turn_id!r}")
        return
    recorder = self._session.recorder
    if not recorder.enabled:
        # debug 关着却收到 fetch —— 前端拿了过期协议，回 found=false 让它消停
        sink(ChahuaEnvelope(
            room_id=..., turn_id=turn_id, type=ChahuaEventType.TURN_DETAIL,
            data={"found": False},
        ))
        return
    turn, prompts = recorder.load_turn(turn_id)
    if turn is None:
        sink(ChahuaEnvelope(
            ..., type=ChahuaEventType.TURN_DETAIL,
            data={"found": False},
        ))
        return
    sink(ChahuaEnvelope(
        ..., type=ChahuaEventType.TURN_DETAIL,
        data={"found": True, "turn": turn, "prompts": prompts},
    ))
```

**为什么不放进 `admin` / `task` 子 slot**：四个 slot 是按"领域"切的（房间 / 任务 /
IO / 设置）—— debug 不属任一领域，是横切观测能力，与 `_inbound_cancel` 同级合理。
将来若再加 `dump_turn_jsonl_to_local` 之类的取证 inbound，可考虑开第五个 slot
`debug.*` 但 P6.3 还不够堆。

### 6. 前端实现

**收敛口径**（评审第 4 条）：**不做滚动触底自动分页 / placeholder 批次展开 / 历史
徽标**。1000 条轻量索引行直接全渲（每行 ~200B DOM，Electron 单 `<aside>` 容纳没问题），
点击行才拉详情。

#### 6.1 `app/renderer/debug_panel.js` 扩展

```js
export function createDebugPanel({ panelEl, bodyEl, clearBtnEl, sendInbound }) {
  // sendInbound: 新增依赖 —— 调用 ws.send({type: "fetch_turn_detail", turn_id})
  // 由 renderer.js 注入，与现有 inbound 走同一份编码 / 错误处理。

  const turns = new Map();           // 既有：实时 + 已展开的历史详情共用
  const turnNodes = new Map();       // 既有
  const messageTurn = new Map();     // 既有
  const dirty = new Set();           // 既有
  // 新增：room_history 来的轻量索引（倒序，≤ 1000 条）。仅 turn_id / ts_ms / winners
  // 等元数据；常驻不参与 evict。详情按需拉。
  const historicalIndex = [];
  // 新增：去重并发 fetch（双击 / 慢网下重复点）。
  const inflightFetches = new Set();
  // 新增：索引行 DOM 反查表 —— 详情拉回来后替换该行；found=false 时移除该行。
  const indexRows = new Map();       // turn_id → <li>

  function applyTurnsIndex(index) {
    historicalIndex.length = 0;
    indexRows.clear();
    if (!Array.isArray(index)) return;
    historicalIndex.push(...index);
    renderHistoricalIndex();         // 1000 条一次性渲（轻量行，无分批）
  }

  function fetchTurnDetail(turnId) {
    if (turns.has(turnId)) return;          // 已加载（实时 or 历史详情）
    if (inflightFetches.has(turnId)) return;
    inflightFetches.add(turnId);
    sendInbound({type: "fetch_turn_detail", turn_id: turnId});
  }

  function handleTurnDetail(env) {
    const turnId = env.turn_id;
    inflightFetches.delete(turnId);
    const data = env.data || {};
    if (!data.found) {
      // rotation 已清 / 服务端找不到 —— 整行 DOM 移除。
      removeIndexRow(turnId);
      return;
    }
    const indexEntry = findIndexEntry(turnId);   // 仍要保留，evict 复原靠它
    const record = buildHistoricalRecord(data.turn, data.prompts || {});
    record.fromHistory = true;
    record.indexEntry = indexEntry;
    turns.set(turnId, record);
    // 同一个 <li>：把内部内容从"轻量索引行"换成"完整详情卡片"。DOM 节点本身保留 ——
    // evict 时还原成轻量行即可，不删节点。
    swapRowToDetail(turnId, record);
    // 评审 #1：历史详情 + 实时 turn 共用一个上限。**先 swap 再 evict** 避免刚拉的
    // 当前 turn 被自己挤出去（evictOldest 是 LRU，把 oldestId 出列）。
    evictOldest();
  }

  function evictOldest() {
    while (turns.size > MAX_TURNS_IN_MEMORY) {
      const oldestId = turns.keys().next().value;   // Map 保插入序
      const record = turns.get(oldestId);
      turns.delete(oldestId);
      messageTurn.forEach((tid, mid) => {
        if (tid === oldestId) messageTurn.delete(mid);
      });
      const node = turnNodes.get(oldestId);
      if (record && record.fromHistory && record.indexEntry) {
        // 还原回轻量索引行 —— 用原 <li> 重渲索引内容，重新挂 click handler
        // 拉详情。节点保留在原位置，不破坏 ts_ms 倒序结构。
        swapRowBackToIndex(oldestId, record.indexEntry);
      } else {
        node?.remove();
        turnNodes.delete(oldestId);
      }
    }
  }

  function onEnvelope(env) {
    switch (env.type) {
      // ... 既有实时分支不动
      case EventType.TURN_DETAIL:
        return handleTurnDetail(env);
    }
  }

  return {
    onEnvelope,
    reset,                                  // 切房清所有状态；下一帧 room_history 重灌索引
    show, hide, isVisible,
    applyTurnsIndex,                        // renderer.js 在 room_history 帧调
  };
}
```

**渲染契约**：
- `historicalIndex` 按 ts_ms 倒序，最新在顶 —— 与实时 turn 同一时间轴；实时 turn 渲
  在最上方，历史索引行紧随其后。
- 历史索引行**轻量** DOM：时间戳 + winners 短串 + `scoring_path` 徽标（一行高），
  点击触发 `fetchTurnDetail`，详情回来后**在同一个 `<li>` 上**把内容换成详情卡片
  （`swapRowToDetail`），不另开容器、不删原节点。
- **统一 evict + 还原索引行（评审 #1 + #3）**：实时与历史详情共用 `MAX_TURNS_IN_MEMORY=50`
  上限。实时 turn 被 evict → DOM 整节点 remove；**历史详情** 被 evict →
  `swapRowBackToIndex` 把 `<li>` 内容还原成轻量索引行（节点位置不动），保留点击复拉
  入口。这一步是评审 #3 直指的承重墙 —— 若 evict 直接 remove DOM，索引行会跟着消失，
  用户"再点重新拉"承诺就废了。`record.fromHistory = true` + 缓存 `indexEntry` 是
  evict 路径分支判断的唯一依据。

## P6.3.B：磁盘 rotation

### 8. 配置

`chahua/config.py` 的 `[debug]` 段加 1 个新字段（**仍是 all-or-nothing 段** ——
段内 `enabled` / `capture_prompts` 任一存在则段视作"写"，未知字段 → `RoomConfigError`）：

```toml
[debug]
enabled = true
capture_prompts = true
max_mb = 20        # 默认 20 MB；0 表示不限（与"删 debug/ 后 enabled=true"等价）
```

- 默认 `max_mb = 20`。理由：单 turn ~30KB jsonl + ~40KB prompts，约 700 turn 触底；
  普通对话节奏跑 1-2 周触上限，触发后自动清理压力小、用户基本无感。
- `max_mb = 0` → 关掉 rotation（**不是关 debug**）。给"我要这个房间的完整调试历史"
  的用户留口子。
- `max_mb < 0` → `RoomConfigError`（同 `temperature` 越界口径）。
- `max_mb` 算 `debug/` 整目录大小（jsonl + prompts/ 子树）。

**不**加：
- 时间窗口（按"保留 N 天"）—— 不直观，长 idle 房间会突然清光最近一天前的。
- 每文件 cap —— turns.jsonl 单文件就这一个，prompts 文件本来就小。
- 按 turn 数 cap —— "MB"是用户能直接看到的盘指标；"turn 数"反而抽象。

### 9. 算法

**核心思路**：按 turn 删，不按文件删；以 `turn_id` 为最小淘汰单位（一个 turn 的
jsonl 行 + 对应 `prompts/<turn_id>/` 子目录是事务）。

```python
class TurnRecorder:
    def rotate_if_needed(self) -> None:
        """超 max_mb 时按 turn_id 倒序保最新，从最老开始删 jsonl 行 + prompts/ 子目录。

        - ``enabled=False`` / ``max_mb=0`` 早 return。
        - 调用点两个：``__init__`` 末尾 + ``flush_turn`` 末尾。
        - 失败不阻断：所有 IO try/except 包到底 + WARN。
        """
```

**触发点**：
1. **`__init__` 期**：boot 时**全量检查一次**，把上次跑下来的超额清掉。这是主路径 ——
   持续跑的房间常态贴近上限。
2. **`flush_turn` 末尾**：**节流检查**（评审第 5 条）—— 不是每条 flush 都全目录扫
   `os.scandir` 几千个 prompt 文件。两条节流条件**或关系**触发一次实测：
   - flush 计数器：每 50 次 flush（≈ 50 个 turn）一次。
   - 时间戳：距上次实测 ≥ 60 秒。
   两者择一先到即触发。前者保证写盘速率高时不漏过上限太多（50 turn × ~70KB ≈ 3.5 MB
   超额上限，相对 20 MB cap 仍可接受）；后者保证写盘速率低（用户偶尔来一句话）时
   也会被定期扫到，避免长 idle 房间永远不清理。

**不**做：
- 后台线程定时扫 —— 多一份并发态、文件锁；房间是单线程，不值。
- 写前先量 —— "确认下次写完后是否超" 复杂度高，且 IO 永远滞后；改用"写完再清"。
- 建 sidecar 索引文件 —— 顺序扫够用（见 §5.1）。

#### 9.1 算法骨架

```python
# 节流状态（TurnRecorder 实例字段）
self._rotate_flush_counter = 0
self._rotate_last_check_ms = 0
_ROTATE_FLUSH_INTERVAL = 50        # 每 N 次 flush 一次实测
_ROTATE_TIME_INTERVAL_MS = 60_000  # 或距上次 ≥ N ms

def _should_rotate_check(self, *, force: bool) -> bool:
    """节流闸门：``force=True``（boot 路径）始终通过；flush 路径按计数器或时间。"""
    if force:
        return True
    self._rotate_flush_counter += 1
    if self._rotate_flush_counter >= _ROTATE_FLUSH_INTERVAL:
        return True
    if now_ms() - self._rotate_last_check_ms >= _ROTATE_TIME_INTERVAL_MS:
        return True
    return False

def rotate_if_needed(self, *, force: bool = False) -> None:
    if not self.enabled or self._max_mb <= 0:
        return
    if not self._should_rotate_check(force=force):
        return
    self._rotate_flush_counter = 0
    self._rotate_last_check_ms = now_ms()
    try:
        cap = self._max_mb * 1024 * 1024
        total = self._measure_debug_dir()    # os.scandir 递归 sum st_size
        if total <= cap:
            return
        # 读 jsonl 投影出 (turn_id, ts_ms)；按 ts_ms 升序删，删到 ≤ 0.9 × cap 停
        # —— 留 10% 缓冲，避免每轮都贴线压一两条，I/O 抖动。
        target = int(cap * 0.9)
        index = self.load_index(limit=None)   # 倒序
        old_to_new = list(reversed(index))
        kept_ids: set[str] = set()
        # 自底向上保留：先把"新"全收入 kept_ids、累加 size；超出 target 之前的就是"删"。
        sizes_by_id = self._measure_per_turn_sizes(old_to_new)
        running = 0
        # 从最新（index[0]）开始保留，反向走
        for entry in reversed(old_to_new):
            size = sizes_by_id.get(entry["turn_id"], 0)
            if running + size > target and kept_ids:
                break    # 加这一条就超 —— 停在"保留集"。最老那批进 to_delete。
            running += size
            kept_ids.add(entry["turn_id"])
        to_delete = [e["turn_id"] for e in old_to_new
                     if e["turn_id"] not in kept_ids]
        if not to_delete:
            return
        self._rewrite_jsonl_dropping(to_delete)
        for tid in to_delete:
            self._rm_prompt_subdir(tid)
        _log.info(
            "TurnRecorder rotated %d turns (%.1f MB → %.1f MB)",
            len(to_delete), total / 1024 / 1024, running / 1024 / 1024,
        )
    except Exception:
        _log.warning("TurnRecorder.rotate_if_needed failed", exc_info=True)
```

**关键决定**：
- **jsonl 用 tmp+rename 整体重写**（不 in-place 删行）—— 一致性与 `cursor.json`
  同口径；中途崩溃留下完整旧文件而非半截。
- **prompts/ 子目录 `shutil.rmtree`**：单子目录最多 N+1 个 .txt（N=guests + 1 个 speak
  + 还有 message_id 多份），整目录删比逐文件 unlink 干净。
- **删失败的 prompts/ 子目录不阻断 jsonl 重写**：可能权限 / 文件被打开 → WARN，下次
  rotation 再尝试。盘上残留几个 orphan `prompts/turn_xxx/` 是可接受的（用户 ls 看到也
  不会迷惑，turn_id 命名自带语义）。
- **倒序保留集算法**：保证"最新 N 条总在"；最坏情况单个最老 turn 已经超 cap 也只删
  它一条不动新的（`if kept_ids` 守卫保留至少一条最新的）。

#### 9.2 与 `turns_index` 的协同

A 子项的 `emit_room_history.turns_index` 在 ws 连上 / 切房时 snapshot **当前盘上还有
什么**。rotation 在 `__init__` 跑过 → snapshot 已是清理后状态。**rotation 在 `flush_turn`
跑** → 新 turn 写完后顺手清；下一次切房 / 刷新 / 连接 snapshot 自然更新。

**前端持有的 `turns_index` 与盘不同步的窗口**：用户开窗（拿到 1000 条索引）→ AI 跑了
500 轮 → rotation 清掉最老 500 条 → 用户翻到底点了某个被清的 turn_id → `FETCH_TURN_DETAIL`
回 `found=false` → 前端去除该 placeholder。**预期路径不报错** —— rotation 与 UI 缓存
天然异步。

### 10. 不变量延伸

加进 CLAUDE.md「关键不变量」节，与 P6.1 / P6.2 同口径：

- **`turns_index` 在 `room_history` 中严格 `enabled=True` 才出现**（同 piggyback 口径）。
  关闭 debug 时整字段缺省，前端区分"关了" vs "开着但确实空"。
- **`TURN_DETAIL.data.prompts` 严格 enabled && capture_prompts && 文件可读三重满足才出现**
  （单 key 级别）：任一不满足 → 该 key 在 dict 缺省（不写空串），前端按
  `prompts[rel] === undefined` 渲禁用 / 不可用提示。
- **`fetch_turn_detail` 的 turn_id 严格 `^turn_[0-9a-f]+$`**：拒穿越 + 拒未来格式（若
  改 id 形态，此 regex 同步动 + 兼容旧值另开判断 —— 不开漏洞窗口）。
- **rotation 按 turn_id 整组删**：jsonl 行 + `prompts/<turn_id>/` 子目录是事务；半截
  失败时下次 rotation 重试。
- **rotation 在 `__init__` 末尾 + `flush_turn` 末尾两点触发**：不开后台线程；不写前
  量；都在串行路径上。`__init__` 路径走 `force=True` 必做一次全量；`flush_turn` 路径
  按"每 50 次 flush **或** ≥ 60 秒"节流（评审第 5 条），避免每条 flush 都全目录扫
  几千 prompt 文件。
- **历史详情走统一 evict**（评审第 1 条）：抽屉里 `MAX_TURNS_IN_MEMORY=50` 对实时 +
  历史详情**共同**生效；索引常驻不 evict。被 evict 的历史详情靠重新 `FETCH_TURN_DETAIL`
  恢复，盘上还在；保证用户连续展开几十上百条 prompt 时前端内存有上限。
- **rotation 失败永远不阻断房间**：所有 IO try/except + WARN（与 recorder 失败不阻断
  房间同口径）。
- **rotation 保留集"至少 1 条最新 turn"**：单 turn 超 cap 时仍保留它不动新的；保留集
  累积到超 `0.9 × cap` 才停，留 10% 缓冲。
- **`max_mb = 0` 关 rotation，不关 debug**：给"全量取证"用户留口子；负数 →
  `RoomConfigError`。
- **`turns_index` 硬上限 1000 条**：超出仅下最新 1000 条；用户翻更老的从盘上 grep，
  不开"翻页"协议。

## 12. 不在 P6.3 内的项

明确推到 P+1 或更后，避免 scope creep：

- **历史 turn 的"翻更老"分页**：`turns_index` 硬上限 1000 条；要看更老的从盘上 grep。
  真有需求加 `FETCH_TURNS_INDEX{before_turn_id, limit}` inbound，本期不做。
- **抽屉滚动触底自动批次展开 placeholder**（评审第 4 条收敛）：本期直接一次性渲全部
  ≤ 1000 条索引行（每行 ~200B DOM）；批次展开 + 滚动 IntersectionObserver 的复杂度真
  撑不到（Electron 单 `<aside>`），等 DOM 长度真成瓶颈再加。
- **跨房间 dashboard**：现在每房间独立 `debug/`，全局视图要新概念（聚合服务 / index
  合并），P6.3 不开口。
- **历史 turn 的 message_delta / thinking_chunks 回放**：实时流字符级 delta 没落盘
  （P6.1 不变量"delta_chars 后续补 hook"），P6.3 不补。
- **完整工具结果 `result` 字段**：仍是 P6.1 的口子（agentao tool_complete 不带 full
  result），与 P6.3 无关。
- **rotation 的"按时间窗口"模式**：仅按盘上 MB；按"保留 N 天"模式留给真有需求时再加。
- **rotation 的后台线程 / 异步扫**：串行触发够用；改异步等真有性能数据再说。
- **`debug/` 备份 / 导出归档**：用户主动 `cp -r debug/ archive/` 即可；自动归档（如
  超 `max_mb` 不删而是 tar.gz 转走）下一阶段如有"调试历史长期归档"需求再加。
- **跨房间 turn_id 唯一性**：当前 `new_turn_id` = `turn_<10字节 hex>` 全局唯一概率上
  够；A 子项 `_inbound_fetch_turn_detail` 只在当前房间 jsonl 里找，跨房间不串。
- **prompt 文件按需懒拉**：`TURN_DETAIL` 一帧把 prompts 全打包；若未来单 turn prompt
  超 200KB（罕见，意味着 N=10 茶客 + 长 transcript）再拆 `FETCH_PROMPT{turn_id, rel}`
  inbound 二阶段拉。
