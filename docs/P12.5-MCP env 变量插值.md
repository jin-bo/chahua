# P12.5：MCP env 变量插值 —— persona / 房间级 mcp.json 的 API key 从环境变量取

> 让 persona sidecar `mcp.json` 与房间级 `[[guest.extra_mcp_servers]]` 的 `env` / `headers` / `args` 支持 `$VAR` / `${VAR}` 插值，真密钥留在 `.env`，包里只声明变量名。把 LLM 侧既有不变量「**API key 永不进 toml / envelope**」延伸到 MCP 侧「**API key 永不进 persona 包 / mcp.json**」。

## 现状与痛点

persona MCP 的装载链路（`chahua/persona_assets.py` → `chahua/session.py` → `chahua/guest.py::_merged_mcp_configs` → `chahua/mcp_thread.py::ThreadedMcpClientManager`）：

1. `discover_assets(persona_path)` → `_load_mcp_servers(mcp.json)`（`persona_assets.py:133`）把 `mcpServers` **原样**读进内存，只做 `dict(cfg)` 浅拷，**不做任何插值**。
2. 信任门（`session.py:159-168`）：未受信任 → `mcp_servers=None`。
3. `_merged_mcp_configs`（`guest.py:54-92`）overlay 三档来源（文件加载 / persona / 房间级），加 `trust` 标志。**这里也不插值。**
4. agentao `McpClient._connect_stdio`（`agentao/mcp/client.py:179-181`）起子进程：`env = dict(os.environ); env.update(config["env"])` —— 子进程**继承父进程 env**，再用 config 的 `env` 覆盖。

痛点：现在 `examples/personas/Yvonne/mcp.json` 里只能硬写占位串

```json
"env": { "AMAP_MAPS_API_KEY": "你的高德地图API密钥" }
```

装包的人必须把真 key 直接写进 `mcp.json`，于是：

- **密钥进了 persona 包**。persona 是可分发资产（`persona_import` 从 GitHub 拉），key 写进去等于跟着包到处跑。
- **占位串覆盖继承值**。即便用户把 `AMAP_MAPS_API_KEY` 放进了 `~/.env`，`env.update(config["env"])`（`client.py:181`）会用占位串覆盖掉继承来的真值 —— 不删占位串永远连不上。
- **没有「声明依赖」的位置**。作者无法表达「这个 server 需要 `AMAP_MAPS_API_KEY` 这个变量」。

## 为什么不是「纯继承」（被否的方案 A）

agentao 子进程已经继承 `os.environ`，而 chahua 启动时 `load_env_files`（`session.py:46-54`）把 `~/.env` + `user_data_root/.env` 灌进 `os.environ`（`override=False`，shell 优先）。所以理论上：把 key 写进 `~/.env`、**删掉** `mcp.json` 里那条 env，子进程就继承到了。零代码改动。

否掉的理由：

- **占位串覆盖坑**（见上）—— 用户体验差，删了才生效，反直觉。
- **变量名不可见**。persona 包没法声明「我需要哪个变量」，装包的人得读源码 / 试错才知道要设什么。
- 与 P12.2 路线图（`[requires].mcp_servers` 装前校验）方向不一致 —— 那一步要能列出「这个 persona 缺哪些前置」，需要变量名是显式声明的。

`${VAR}` 插值把「需要哪个变量」写进 mcp.json，自文档化、可被 P12.2 复用，且与 LLM 侧 `api_key_env` 同哲学。**故选方案 B。**

## 复用 agentao 还是自己写（关键依赖决策）

agentao 其实**已经有**这套插值引擎，只是 chahua 的 persona / 房间级路径没接上：

- `agentao/mcp/config.py:34` `expand_env_vars(value)` —— `$VAR` / `${VAR}` 替换，缺变量返空串。**public**（无下划线）。
- `agentao/mcp/config.py:42` `_expand_config_env(config)` —— 对 `env` / `headers` / `args` 三类字段批量展开。**private**（下划线）。
- 这套引擎当前**只在** `load_mcp_config`（`config.py:132`）里对 `.agentao/mcp.json` 文件加载生效；persona / 房间级 server 是 chahua 在 `_merged_mcp_configs` 里 overlay 的，绕过了它。

决策：

- **substitution 原语复用 `expand_env_vars`（public）** —— `${VAR}` 的正则 / 缺变量语义与文件加载路径保持**同一来源**，不让两条路径漂移。
- **字段应用 + 缺变量 WARN 由 chahua 自己做**，不依赖私有 `_expand_config_env` / `_ENV_VAR_RE`。**Why**：① 私有符号无稳定性承诺，agentao 改名即炸；② chahua 要在「引用了变量但展开成空」时 WARN（`_expand_config_env` 静默），这是 chahua 自己的诊断关切。代价是一段几行的「挑字段」逻辑 —— 比耦合私有符号划算。

> 若未来 agentao 把 `_expand_config_env` 提为 public 且支持 WARN hook，可回收 chahua 这段。届时一个测试钉住「persona `${VAR}` 与文件加载 `${VAR}` 行为一致」即可放心切换。

## 承重不变量

- **`mcp.json` / `[[guest.extra_mcp_servers]]` 的 `env` / `headers` / `args` 字符串值支持 `$VAR` / `${VAR}`，在装载茶客 MCP 时一次性展开**。`chahua/guest.py::_merged_mcp_configs` 对 persona_servers / room_level_servers 各跑一次展开后才喂 `ThreadedMcpClientManager`。**Why**：把密钥从可分发的 persona 包 / 用户 toml 里赶出去，只留变量名引用 —— LLM 侧「API key 永不进 toml / envelope」在 MCP 侧的对等物。
- **文件加载层（`.agentao/mcp.json`）不重复展开**。`load_mcp_config` 已在 `config.py:132` 展开过；`_merged_mcp_configs` 只对自己 overlay 的 persona / 房间两层展开，保证**每层恰好展开一次**。**Why**：二次展开会把首轮展开后值里偶然出现的 `$` 误当变量；语义上「谁加进来谁负责展开一次」最清晰。
- **变量未设置或为空串 → 展开为空串 + WARN，不报错、不阻断房间**。沿用 agentao `expand_env_vars` 的空串降级（`config.py:38` `os.environ.get(var, "")`）；chahua 额外在引用的变量「未设置**或**已设为空串」时 WARN 一次（用 `not os.environ.get(var)` 判定，**不是** `var not in os.environ` —— `export KEY=` 这种设了空值的也得 WARN，否则空 API key 静默失败无诊断）。同名变量在一个值里多次出现只 WARN 一次。**Why**：MCP 装载失败不该炸掉整个房间（与「持久化加载跳坏行」「rotation 失败永不阻断」同一容错档）；但空 API key 会让 server 运行时静默失败，WARN 是必要诊断。
- **`$VAR` / `${VAR}` 是 shell 风格无转义展开**。值里字面 `$` 后跟标识符字符（如硬写口令 `"p$assword"`）会被当变量引用、展开成空 —— 与 agentao 文件加载层（`load_mcp_config`）**完全同语义**，不是 chahua 自造行为。**Why**：persona / 房间两层 P12.5 前是 verbatim、不展开，本步把它们对齐到 agentao 文件层口径。不引入转义方言（`\$` 等）—— 真有字面 `$letter` 需求再说（非目标）。需要字面 `$` 的极少数场景：把整值放进 `.env` 由继承带入，mcp.json 里不写该字段。
- **展开发生在信任门之后**。`session.py` 未受信任时已把 `persona_servers` 置 `None`，`_merged_mcp_configs` 只对受信任的 persona server 展开。**Why**：插值 = 把宿主 env 注入子进程，必须在用户已勾选信任该 persona MCP 之后才做。房间级 `extra_mcp_servers` 是用户手写 = 自动信任，照常展开。
- **展开读 `os.environ` 的时机 = 茶客构造时**。两个入口（`server_entry.py:80` / `cli.py:229`）都先 `load_env_files` 再 `build_room_session`；切房 / `_replace_session` 运行期重建 session 时 `os.environ` 已就绪。**Why**：`load_env_files` 用 `override=False` 且只在进程启动调一次 —— 展开看到的是「启动那一刻的 .env + shell」快照，不热加载 .env 改动（与 LLM key 同口径）。
- **展开后的值绝不下发前端**。`server_room_snapshot.py::_mcp_summary_list`（`:50-66`）只投影 `name` / `command` / `args` 且**显式剔除 `env`**；且它读的是 `discover_assets` 的 raw 配置（未展开），故 args 里的 `${VAR}` 以字面量出现，连展开后的真值都不经过 envelope。**Why**：envelope 一旦带密钥，前端 devtools / log dump / 跨用户 user_data 共享都能看到（设计 §2.2）。**改 `_mcp_summary_list` 投影字段时必须同步审计是否引入 env 泄漏。**

## 文件格式

persona sidecar `mcp.json`（dir-form persona 才扫）：

```json
{
  "mcpServers": {
    "amap-maps": {
      "command": "npx",
      "args": ["-y", "@amap/amap-maps-mcp-server"],
      "env": { "AMAP_MAPS_API_KEY": "${AMAP_MAPS_API_KEY}" }
    }
  }
}
```

房间级 `room.toml`（用户手写，自动信任）：

```toml
[[guest.extra_mcp_servers]]
name = "amap-maps"
command = "npx"
args = ["-y", "@amap/amap-maps-mcp-server"]
env = { AMAP_MAPS_API_KEY = "${AMAP_MAPS_API_KEY}" }
```

真密钥放 `~/.env` 或 `user_data_root/.env`：

```
AMAP_MAPS_API_KEY=真实key
```

两种语法都支持：`${AMAP_MAPS_API_KEY}`（推荐，边界清晰）与 `$AMAP_MAPS_API_KEY`。也支持拼接：`"Bearer ${TOKEN}"`。

## 模块改动

### 改 `chahua/guest.py::_merged_mcp_configs`（唯一实现点）

新增一个模块级 helper + 在 overlay persona / room-level 时各调一次：

```python
import os
import re
from agentao.mcp.config import expand_env_vars   # public 原语，与文件加载同源

# 仅用于「缺变量 WARN」的扫描；substitution 仍走 agentao expand_env_vars。
_ENV_REF_RE = re.compile(r"\$\{([^}]+)\}|\$([A-Za-z_][A-Za-z0-9_]*)")
_MCP_EXPAND_DICT_FIELDS = ("env", "headers")


def _expand_mcp_server(server_name: str, cfg: dict) -> dict:
    """对单个 MCP server cfg 的 env / headers / args 做 $VAR / ${VAR} 展开。

    substitution 复用 agentao.expand_env_vars（与 .agentao/mcp.json 文件加载同语义）；
    本函数只挑字段 + 在「引用变量但展开为空」时 WARN（agentao 静默）。缺变量不报错。
    """
    out = dict(cfg)
    for field in _MCP_EXPAND_DICT_FIELDS:
        val = out.get(field)
        if isinstance(val, dict):
            out[field] = {
                k: _expand_one(server_name, f"{field}.{k}", v) for k, v in val.items()
            }
    args = out.get("args")
    if isinstance(args, list):
        out["args"] = [_expand_one(server_name, "args", a) for a in args]
    return out


def _expand_one(server_name: str, where: str, value):
    if not isinstance(value, str):
        return value
    if _ENV_REF_RE.search(value):
        for m in _ENV_REF_RE.finditer(value):
            var = m.group(1) or m.group(2)
            if var not in os.environ:
                _log.warning(
                    "MCP server %r 的 %s 引用未设置的环境变量 ${%s}，将展开为空串",
                    server_name, where, var,
                )
    return expand_env_vars(value)
```

`_merged_mcp_configs` 改动（只在 persona / room-level 两层加 `_expand_mcp_server`，文件加载层 `configs` 不动 —— 已被 `load_mcp_config` 展开）：

```python
    merged = dict(configs)                       # 文件加载层：load_mcp_config 已展开
    if persona_servers:
        for name, cfg in persona_servers.items():
            cfg = _expand_mcp_server(name, cfg)   # 新增
            if name in merged:
                _log.info("persona MCP server %r overrides file-loaded config", name)
            merged[name] = {**cfg, "trust": cfg.get("trust", True)}
    if room_level_servers:
        for name, cfg in room_level_servers.items():
            cfg = _expand_mcp_server(name, cfg)   # 新增
            if name in merged:
                _log.info(
                    "room-level MCP server %r overrides persona / file-loaded config", name
                )
            merged[name] = {**cfg, "trust": True}
    return merged
```

**不动**：`persona_assets.py`（仍原样读 raw mcp.json —— snapshot 投影要 raw，展开只在装载侧）；信任门；`mcp_thread.py`；`server_room_snapshot.py`（已剔 env）。

## 测试

新增 `tests/test_mcp_env_expand.py`：

- `_merged_mcp_configs` 对 persona server 的 `env["K"]="${FOO}"`，`os.environ["FOO"]="bar"`（monkeypatch）→ 喂给 manager 的 cfg `env["K"]=="bar"`。
- `$FOO` 裸形式同样展开。
- 拼接 `"Bearer ${TOK}"` → `"Bearer xyz"`。
- `args` 里的 `${VAR}` 展开；非 str 元素（理论上不该有）原样保留不抛。
- `headers`（SSE 形态）里的 `${VAR}` 展开。
- **缺变量 → 展开空串 + WARN 一次**（`caplog` 验 WARN 文本含变量名 + server 名），不抛。
- **文件加载层不二次展开**：构造 `configs`（模拟 `load_mcp_config` 已展开结果）里含字面 `$` 的值，断言原样保留（即 `_merged_mcp_configs` 没碰文件加载层）。
- 房间级 `room_level_servers` 同样展开（与 persona 同口径）。
- **信任门交互**：未受信任时 `persona_servers=None`（由 `session` 置），`_merged_mcp_configs` 不展开任何 persona server（无 server 进 merged）。
- **raw 不被改写**：传入的 persona_servers dict 本身不被原地修改（`_expand_mcp_server` 走 `dict(cfg)` 拷贝）—— 保证 `discover_assets` 的 raw 配置仍供 snapshot 投影用字面 `${VAR}`。

`tests/test_room_snapshot.py`（已有，补一条）：

- persona mcp.json `env` 含 `${SECRET}`、`os.environ["SECRET"]="真值"` → `room_info` 的 `persona_mcp_servers` 投影里**不含 env、不含 "真值"**；`args` 若有 `${VAR}` 以字面量出现（验展开不经过 snapshot）。

## 迁移

| 现状 | P12.5 后 |
|---|---|
| `mcp.json` 里硬写真 key | 仍可用（字面量无 `$` 不受影响）；建议改 `${VAR}` 把 key 挪进 `.env`。|
| `mcp.json` 里硬写占位串 `"你的…密钥"` | 不再是必须；改 `${VAR}` + `.env` 后即插即用，无覆盖坑。|
| `.agentao/mcp.json` 文件加载 `${VAR}` | 行为零变化（一直由 `load_mcp_config` 展开）。|
| 值里本就含字面 `$`（无变量引用形态） | `_ENV_REF_RE` 不命中 → `expand_env_vars` 不改写 → 原样保留。|

无破坏性变更，无需 bump 任何 schema。

## 非目标（明确不做）

- **`.env` 热加载 / 文件监听** —— 展开读启动快照，与 LLM key 同口径。改了 .env 重启房间（切房重建 session 即重新展开）。
- **缺变量时拒绝装载该 server** —— 走空串降级 + WARN，不阻断（容错档一致）。真要装前校验是 P12.2 `[requires]` 的事。
- **`[requires].mcp_servers` 装前列依赖 / 引导设变量** —— P12.2，本步只做运行期插值。
- **把展开下沉到 `persona_assets.discover_assets`** —— 那样 snapshot 投影会拿到展开后的真值（args 等），增加泄漏面。展开严格留在装载侧（`_merged_mcp_configs`）。
- **默认值语法 `${VAR:-default}`** —— agentao `expand_env_vars` 不支持；无真实需求前不自造方言。
- **字面 `$` 转义（`\$` / `$$`）** —— 字面 `$letter` 会被展开成空，与 agentao 文件层同坑；不为这个边角自造转义方言。需要字面 `$` 走 `.env` 继承（mcp.json 不写该字段）。

## 风险与缓解

- **二次展开污染**：若误对文件加载层再展开，首轮结果里偶然的 `$` 会被误解析。缓解：`_merged_mcp_configs` 严格只对 persona / room-level 两层调 `_expand_mcp_server`，测试钉住「文件加载层字面 `$` 不被改写」。
- **缺变量静默空 key**：用户忘设 `.env`，server 拿空 key 运行期失败、表象像「MCP 连上了但调用全错」。缓解：「引用变量但展开为空」WARN 一次，文本含变量名 + server 名，引导用户查 `.env`。
- **私有符号耦合**：只 import public `expand_env_vars`；字段应用 + WARN 用 chahua 自己几行 + 本地 `_ENV_REF_RE`，不碰 agentao 私有 `_expand_config_env` / `_ENV_VAR_RE`。
- **env 泄漏前端**：`_mcp_summary_list` 已剔 env，但本步明确把「投影字段变更须审计 env 泄漏」写进承重不变量，防未来加字段时回归。
