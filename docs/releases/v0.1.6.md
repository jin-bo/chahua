# v0.1.6 —— 多模态图像输入（视觉茶客看像素 / 非视觉退化文本）（2026-05-31）

继 v0.1.5「persona 包化 + MTS 待机闭环」之后第七个版本。本版一条主线：**P13 多模态图像输入** —— 让用户发的图，在视觉能力的茶客模型那里**真正看到像素**，不支持视觉的茶客模型自动退化为文本引用（逐茶客独立，因为每个茶客包自己的 model）。降级零自研，全交给 agentao（≥0.4.8）的 reactive「图→文本引用」回退；视觉附图纯瞬态、不入库、不改任何 schema。期间还把 `persona_import.py` 按子域拆出 helper、精简 CLAUDE.md 不变量并把明细移进 `docs/INVARIANTS.md`。1431 测试全过（v0.1.5 收线 1371 → +60）。

## 亮点

- **用户发图，视觉茶客直接看到像素**：本轮触发用户消息里的图片，在茶客 `speak()` 时作为 OpenAI `image_url` content block 附给该茶客的 model。视觉模型看图、非视觉模型退化为 `- share/x.png (image/png)` 文本引用 —— 因每个 `TeaGuest` 包独立 `Agentao`（各自 LLMSpec/model），「视觉看图、非视觉退化」天然逐茶客发生，chahua **不做能力探测表**。
- **降级零自研，归 agentao**：chahua 只把 `images=[{data, mimeType, _source}]` 传进 `arun()`；模型拒图后的「换文本引用并重试」由 agentao `_runner.py` / `_retry.py` 完成。不写 `_is_image_unsupported` 同义物、不维护 per-provider 视觉能力表。
- **视觉附图纯瞬态，不持久化**：`images_rel` 是 Python 形参，沿当前 turn 同步透传后即弃，**不动 `Message` / transcript / envelope / `schema_version`**。base64 只在 `speak()` 时从 `share/` 实路径懒读现传；transcript 只留 `<./share/..>` 文本标记（非视觉茶客 / 打分 / 历史轮次靠它感知「这里有张图」）。
- **附图范围有界可预测**：只进 `_run_ai_chain` 第一周期（回应用户那批 let_speak）。AI 接力 / pre-drain / re-drain / dormant MTS kickoff / handoff / MTS / bg run 一律退文本标记 —— 像素只属用户那条消息，省 token、撞不上 16 图 / 20MB 上限。**打分永不吃图**。
- **粘贴 / 拖拽上传 + 缩略图**：前端 picker / paste / drag-drop 共用一条 `uploadFiles(files)`；objectURL 缩略图 pill（FIFO 透传 + revoke 防泄漏），超 20MB 的图 pill 提示「茶客看文本引用」。

## 已知未做

- **bg run / handoff / MTS 不接像素**：`images_rel` 只进 `_run_ai_chain` 第一周期，一切调度触发路径（pre-drain / re-drain / dormant MTS kickoff / handoff / bg run）只看 `<./share/..>` 文本标记。bg run 若要支持图，另开增量。
- **历史轮次的茶客退文本引用**：历史图对后续 turn 的茶客同样退回文本标记 —— transcript 只留标记、base64 不入库，reconnect / 历史重建走文本视图。
- **图类型按扩展名白名单识别**：线协议无 MIME，按 `{png, jpg, jpeg, gif, webp}` 扩展名筛 + resolve 时映射 MIME，不做内容嗅探；SVG 不作视觉输入（可内嵌 `<script>`）。
- **packaged 安装包未 Apple Developer ID 签名**：.dmg 仍未签名（同 v0.1.3 ~ v0.1.5，无 Developer ID），首次启动需用户在「系统设置 → 隐私与安全性」放行。
