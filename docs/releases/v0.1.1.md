# v0.1.1 —— 任务房间 + 调试与回放（2026-05-19）

继 v0.1.0 之后第二个版本。本版把房间从"纯聊天容器"升级为"带任务的工作容器"，并补上多 Agent 系统最痛的取证视图——每一轮都能展开看"为什么是这位茶客接话 / 喂他的 prompt 是什么 / 用了哪些工具 / 落了哪些产物"。

## 亮点

- **任务房间**：右上角面板「+ 新任务」开任务 → composer 顶部 chip 显示当前 active 任务；茶客感知 active 任务（onboarding/incremental prompt 都注入 task 块），可写 `./task/<name>` 自动归集为 artifact、可 propose 决策 / 新任务待你「采纳」。产物列表点击即下载（带白名单 + symlink 防逃逸）。多任务共存，单时刻最多 1 个 active。
- **调试抽屉**：与任务面板互斥占右侧槽位，看每一轮谁被候选 / 分数 / 选谁 / prompt / 用了哪些工具 / 产物路径；切房 / 重启后仍能翻"开窗前"的历史 turn（点击索引行即拉详情）。默认开，盘上落到 `rooms/<id>/debug/`；`max_turns = 500` 按 turn 自动 rotation；`room.toml [debug] enabled = false` 可关。
- **专业茶客配置闭环**：每位茶客可独立配 LLM client（模型 / base_url / api_key_env / temperature）；房间可独立配 `[room.llm]` / `[scoring]` / `[summary]`；隔离方式（`isolation = "room"|"global"`）决定记忆走房间内还是用户全局；persona MCP / skills 装载 + 信任门；`[[guest.extra_mcp_servers]]` 在 toml 内联挂 MCP server（自动信任，区别于 persona MCP）。
- **任务事件全房广播**：开 / 关任务 / 加决策 / 挂产物都合成"📋 / ✅ / ✗ / 📌 / 📎"前缀的 user 消息进 transcript，茶客 LLM 看见 + 触发 scoring 循环。
- **`task_write_artifact` 工具**：茶客落盘产物的官方通道，绕开 agentao PathPolicy；name 校验拒 `/` / `\\` / `..` / 前缀 `.`；read-only 权限模式自动拦截。
- **房间共享文件 + 多行输入 + 双击 popover**：每间房 `rooms/<room>/share/` 共享目录 + composer 多文件上传（≤ 200MB / 文件）；composer 切 `<textarea>` 支持多行（Enter 发送 / Shift+Enter 换行）；双击房间名 / 用户头像弹动作 popover（编辑 room.toml / 清空聊天 / 换头像）。

## 里程碑（按提交序）

- **P4 专业茶客配置闭环**（P4.1~P4.9）：`room.toml` 字段一次落地——`[room]` 编排参数 / `[scoring]` / `[summary]` / `[[guest]]` LLM 字段 all-or-nothing 校验 + section fallback；`isolation` / `[[guest.extra_mcp_servers]]`；P4.8 temperature 字段；P4.9 `[room.llm]` 房间默认（toml → env → `RoomConfigError` 三层 fallback）。两个新「详细设置」modal + raw textarea 编辑器 power-user 兜底。
- **persona MCP & skills + MCP 信任门**：persona 目录可放 sibling `mcp.json` 与 `skills/`；skills 软链装载，MCP 因「任意可执行」必须 popover 显式勾选信任才装载。信任记录跨房间持久化在 `user_data_root/.chahua/persona-trust.json`。
- **P5 任务房间**（P5.1~P5.7）：
  - **P5.1 MVP**：`tasks/state.json` + `tasks/<id>/{task.json, decisions.jsonl, artifacts/}`；wire 帧 `open_task` / `update_task` / `attach_artifact` / `add_decision`；权威快照 `task_info` + 4 个 hint；写权限永远在用户。
  - **P5.2 多任务**：`set_active_task` / `close_task`；通道 2 茶客 `./task/` 软链跟 active；任务级 `summary.jsonl` + cursor 落盘。
  - **P5.3 茶客侧感知**（通道 1 + 3）：onboarding ≤300 token / incremental ≤80 token 两路 task 块；三个 task-aware 工具（`task_list_artifacts` / `task_propose_decision` / `task_propose_open`）；前端 proposal 卡片"采纳 / 忽略"。
  - **P5.4 茶客自动归集 + XML 化 context_message**：`_kick_detect_new_artifacts` 每个 pick 周期末尾扫 artifacts dir diff，自动 emit `task_artifact_added` + 重发 `task_info`；context_message 6+1 块 XML 结构（`<room>` / `<user_persona>` / `<room_summary>` / `<current_task>` / `<order_hint>` / `<recent_messages>` / `<speak_instruction>`）+ `quoteattr` 防注入。
  - **P5.5 任务事件全房广播**：合成 user 消息进 transcript；emoji 前缀 + 文案集中到 `task_event_text.py`。
  - **P5.6 打分结合任务要求**：scoring prompt 极简 `<current_task>` XML 块；scoring 与 speak 都加 `<order_hint>` meta 规则（goal 里"先 X 再 Y"角色顺序当硬信号）。
  - **P5.7 拆分**：`orchestrator.py` / `server.py` / `style.css` 切大模块；`composer_task_chip.js` 抽出。
- **P6 调试与回放**（P6.1~P6.3.A）：
  - **P6.1 后端落盘**：`chahua/debug_recorder.py` + `[debug]` config + orchestrator/guest/transport hooks；落 `debug/turns.jsonl` 与 `prompts/<turn_id>/*.txt`；cancel 路径也走 `flush_turn`。
  - **P6.2 前端实时调试抽屉**：消费实时 envelope 流（`TURN_START` / `MESSAGE_*` / `TOOL_*`），与 task_panel 互斥占右侧槽位；envelope piggyback `scoring_prompts` / `speak_prompt` 让前端不另开 inbound 拉文件。
  - **P6.3.A 历史 turn + 磁盘配额**：`room_history.data.turns_index` 投影 + `FETCH_TURN_DETAIL` inbound + `TURN_DETAIL` envelope；前端历史索引行 + 详情卡片统一 evict / 还原索引行；按 turn_id 整组 rotation（`max_turns = 500`）；`clear_room` 同步擦 debug 取证。
- **`task_write_artifact` 工具**：补 P5.4 一直存在但未被测试捕获的 bug —— `./task/<x>` 走 agentao `write_file` 会被 `PathPolicy` 拦（symlink resolve 后 outside working_directory）；改走 chahua 自管的工具直接 `Path.write_text` 绕开 path_policy，自管 name 校验。
- **`./task/` 落盘文案 / `format_messages` XML 包裹 / 打分喂完整 goal**：三项 prompt 工程修复（typical 审稿委员会场景下"应该最后总结"的角色被优先选中、长 markdown body 与下一条消息边界模糊、5000 字报告塞回聊天而非落盘）。
