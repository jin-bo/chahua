# v0.1.12 —— Agentao 0.5.3 升级 + 安装包构建来源可信（P19）（2026-09-22）

继 v0.1.11「flint 数据图表渲染（P10.2）+ MTS 预算收尾轮（P8.7）」之后第十三个版本。**这是一版地基版：没有用户可见的新功能**，价值在两处——① 把落后 9 个版本的 agentao 拉到 0.5.3；② 让安装包里装的东西第一次等于被测过的东西。运行期行为、wire 协议、`schema_version`、数据格式一律不动，**生产代码零功能改动**（唯一改的是 `mcp_thread.py` 的模块说明）。1582 条测试全过，另有真实 LLM 与桌面壳实测。

## 亮点

- **dmg 里的 agentao 第一次与测试跑的是同一份**。P19 之前 `build-python-bundle.js` 把同级 `../agentao` **源码**装进 bundle，而 `uv.lock` / dev venv / 全部测试跑 PyPI 发布版——两者必然偏斜。v0.1.11 的发布说明把这条记在「依赖」段并注明「一贯如此」：dmg 内是 `0.4.20.dev0`，测试跑的是 `0.4.18`。**也就是说历次安装包里的 agentao 从未被任何一条测试覆盖过**。本版改成依赖只认 `uv.lock`（`uv export --locked` + `pip --require-hashes`），chahua 自身 `uv build --wheel` 后 `--no-deps` 装，不给 pip 第二次自由解析的机会。
- **构建指纹取代「文件存在即跳过」**。旧判据要求每版手动 `FORCE=1`，漏一次就把上一版的 python 打进 dmg（v0.1.11 若漏则 P8.7 整个不在包里）。新指纹覆盖锁文件 / chahua 构建输入 / python 版本 / OS·架构 / 构建脚本自身 / agentao 来源，改任一项自动重建；**`FORCE=1` 不再是每版必须**。`bundle-manifest.json` 只在 `pip check` + 版本断言 + sidecar 启动全过之后才写，半截失败的产物永远命不中缓存。
- **出包门 `npm run check:bundle`**：三条机械校验挡在 `electron-builder` 之前——联调源码不得发布 ∧ agentao 版本 == `uv.lock` 锁定版 ∧ bundle 内 chahua 版本与 `app/package.json` 同版（`0.1.12-dev` ↔ `0.1.12.dev0` 按 `{core, dev}` 归一化比，只去一半后缀也拦）。挂四个发布脚本；`build:dir` 不挡，本地联调仍能一路走到可运行的 .app。
- **新增两层「真实依赖」契约测试**。此前 speak 与 MCP 路径的测试全用替身（`agent.arun` 是 `AsyncMock`、MCP 是 `_FakeClient`），替身不会跟着 agentao 演进，升级时接口漂移照样全绿。本版补：真 `Agentao` + 本地假 OpenAI SSE 端点（流式往返 message 成对 / 工具轮 `TOOL_START`·`TOOL_COMPLETE` 与结果回灌 / read-only 拦 `write_file`），以及真 `McpClient` + 本地 stdio server（ws 事件循环内连接调用 / 关停无残留线程无 cancel-scope 错 / 连接失败路径）。

## 依赖

- **agentao `0.4.18` → `0.5.3`**（约束 `>=0.5.3,<0.6`）。锁文件变更最小：仅 agentao 升级 + 新增传递依赖 `anthropic 1.7.0`、`docstring-parser 0.18.0`，以及仅 `sys_platform == 'win32'` 生效的 `tree-sitter 0.26.0` / `tree-sitter-powershell 0.26.4`；其余包未动。`mcp` 解析到 `2.0.0`（0.5.3 允许 `>=1.26,<3`）。
- **对 dmg 用户的实际增量是 0.4.20 → 0.5.3**（旧包里已是 0.4.19 内容）；对 `uv sync` 的 CLI 用户是 0.4.18 → 0.5.3。这段区间**大部分修复落在 chahua 不使用的面上**（CLI 命令、sub-agent、`/skills` 交互），诚实地说：用户能直接感到的变化很少。
- **两条常被当作本版收益的 MCP 修复，chahua 其实早已免疫**：上游 0.4.24 修的「一次回复里两个 MCP 工具调用会丢一个」与「断开 MCP 时记 `Attempted to exit cancel scope`」，正是 P17 的 `mcp_thread.py` 在本仓侧已经做过的事（常驻 loop 线程 + owner-task 同 task 进出 exit stack）。上游原生实现之后，该 shim 成了退役候选（见 P19 §5），本版按「改动面最小」保留，并用真 client 用例钉住双层 owner 下的行为。
- **npm 零新增依赖。**

## ⚠️ 升级注意

- **打包方式变了，发版流程随之变**：`FORCE=1` 不再是每版必须（构建指纹自动失效）；核版本改看 `app/python-bundle/bundle-manifest.json` 的 `agentaoVersion` / `chahuaVersion`；本地联调 agentao 须显式 `CHAHUA_AGENTAO_SOURCE=<path>`，且带该变量产出的 bundle 会被出包门拒绝。
- **`agentao>=0.5.3,<0.6` 是硬下限**：0.5.0 删掉了 `agentao.harness` / `agentao.session` 与八个旧 callback 参数。chahua 生产代码未使用这些入口（已扫描核对），但若你在本仓之外自行拼装 `Agentao`，升级前请对照上游迁移指南。
- **旧房间数据可直接用**：117 MB 真实用户数据副本（28 个 `memory.db`、13 个导入 persona、旧 transcript）在 0.5.3 下跑通，历史回放、`@` 路由、打分、记忆召回、落盘均正常，**未发现任何数据迁移需求**。

## 已知未做

- **Windows 原生构建未验**：`build-python-bundle.js` 按 `process.platform` 拉原生 python，Windows bundle 只能在 Windows 上产；本版的 CRLF 锁文件正则与出包门在 Windows 上未实跑。接缝自 v0.1.0 起就位，仍缺一次真跑（同 v0.1.0 ~ v0.1.11）。
- **HTTP/SSE 传输的 MCP 未在 0.5.3 下实测**：本版只实测了 stdio（真 `McpClient` + 本地 server）；GuanLan（P17）走 Streamable HTTP，需真实 server 才能验。
- **`mcp_thread.py` 尚未退役**：上游已原生具备该能力，退役需先实测等价并改写 P17 owner-task 不变量（P19 §5）。
- **原生 Anthropic Messages / OpenAI Responses 协议与 usage 展示未接入**：0.5.x 新增的 `api_format=` 与 `usage_snapshot()` 本版不使用，接入须走完 `LLMSpec → 配置白名单 → session/build_client → admin/toml → UI/凭证入口` 的一致设计（P19 §5）。
- **P18 M1.5 / M2 仍为设计**：导出过滤与元数据、全局 / 正则 / 跨房搜索。
- **P17 的 P-mem.3 / P-mem.4 暂缓**。
- **packaged 安装包未 Apple Developer ID 签名**：.dmg 仍未签名（同 v0.1.3 ~ v0.1.11），首次启动需用户在「系统设置 → 隐私与安全性」放行。
